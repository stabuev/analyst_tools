# CSV и неоднозначность типов

> CSV становится данными только после явного договора о байтах, разделителях, пропусках и типах.

**Тип:** Learn  
**Треки:** Core  
**Пререквизиты:** 04/13<br>
**Время:** ~75 минут  
**Результат:** объявляет диалект, кодировку, схему и правила пропусков CSV и обнаруживает
поврежденные строки до анализа.

## Цели обучения

- Разделять байтовую кодировку, CSV-диалект и табличную схему.
- Проверять одинаковую ширину строк до типизации значений.
- Задавать маркеры пропуска и числовой формат как часть контракта источника.
- Читать CSV в pandas без молчаливого пропуска строк и необратимой ранней инференции.

## Как этот урок продолжает маршрут

В `03/02` вы уже отделяли исходный токен от dtype и явной политики пропусков, а в
`03/09` и `04/09` требовали у временной метки явный UTC offset. В `04/13` вы находились
на стороне поставщика: сами создавали проверенный CSV-пакет вместе с запросом, manifest
и checksums.

Теперь роль меняется. Аналитик получает чужой файл без исполняемой истории его создания.
Нельзя считать, что расширение `.csv` доказывает encoding, dialect, типы или даже
одинаковую ширину строк. Поэтому прежние контракты не изучаются заново, а переносятся на
более раннюю границу:

```text
неизвестные байты -> проверенная структура -> проверенные токены -> аналитическая таблица
```

В `05/02` тот же принцип понадобится для Excel: вместо delimiter придётся явно выбрать
лист, диапазон и политику формул.

## Проблема

Поставщик прислал файл заказов с расширением `.csv`. На одной машине он открывается, на
другой падает с `UnicodeDecodeError`, а при `pd.read_csv(path)` вся строка оказывается в
одном столбце. После указания `sep=";"` суммы всё равно остаются строками:

```text
1 200,50
950,00
```

В комментарии встречается `скидка; май`, а два пропуска записаны по-разному: пустой
строкой и словом `NULL`. Одна поврежденная строка содержит неэкранированный `;`.

Если решить проблемы набором случайных параметров, файл может загрузиться, но результат
не станет проверяемым. Опасные варианты:

- декодировать с `errors="replace"` и потерять исходные символы;
- использовать неверный delimiter и получить один широкий столбец;
- включить `on_bad_lines="skip"` и незаметно потерять заказ;
- разрешить parser inference превратить идентификатор или маркер пропуска не в тот тип;
- удалить запятые, смешав разделитель полей и десятичный знак.

## Концепция

CSV не хранит единую самодостаточную схему. Для воспроизводимого чтения нужны четыре
отдельных договора.

| Слой | Вопрос | Пример |
|---|---|---|
| Encoding | Как байты превращаются в символы? | `cp1251` |
| Dialect | Как символы делятся на поля и строки? | delimiter `;`, quotechar `"` |
| Null policy | Какие токены означают отсутствие значения? | `""`, `NULL` |
| Schema | Какие столбцы и типы ожидаются? | `amount: decimal`, non-null |

**Encoding** применяется раньше CSV-парсера. Если байты CP1251 попытаться строго
декодировать как UTF-8, ошибка полезна: она останавливает порчу данных. Символ замены
`�` не является исправлением.

**Dialect** определяет delimiter, quotechar, правила двойных кавычек и пробелов. Символ
delimiter внутри quoted field не создаёт новое поле:

```csv
O2002;U002;2026-05-02T08:30:00Z;950,00;RUB;"скидка; май"
```

**Null policy** является семантикой источника. Токен `NULL` иногда означает пропуск, а
иногда является настоящей строкой. Автоматический словарь NA нельзя считать универсальным.
Контракт этого урока намеренно задаёт один список маркеров для всего файла. Если один и
тот же токен означает пропуск только в части столбцов, источник требует отдельной
поколоночной политики — глобальный список нельзя применять молча.

**Schema** применяется после структурной проверки. Сначала нужно доказать, что заголовок
и ширина строк согласованы, затем приводить `amount` и `ordered_at`. Для `ordered_at`
контракт повторяет уже знакомое правило: непустая ISO 8601 строка должна содержать `Z`
или числовой UTC offset.

Число строк — отдельная проверка поставки, а не обязательное свойство формата CSV. Для
фиксированного выгружаемого пакета можно потребовать ровно пять строк. Для ежедневного
источника допустимо задать только минимум или вообще не объявлять row-count policy:
непредсказуемый объём нельзя превращать в ложную ошибку схемы.

В учебной поставке эти два решения видны прямо в JSON-контракте:

```json
{
  "row_count": {"mode": "exact", "value": 5},
  "columns": {
    "ordered_at": {
      "type": "timestamp",
      "nullable": false,
      "require_timezone": true
    }
  }
}
```

Для меняющегося потока замените `exact` на осмысленный `min` либо удалите `row_count`.
`require_timezone: true` не угадывает зону naive-строки, а требует, чтобы источник
передал однозначный момент.

`csv.Sniffer` и parser inference полезны для разведки, но эвристика не заменяет контракт:
результат угадывания нужно проверить и зафиксировать.

## Соберите это

Committed fixture использует CP1251, `;`, десятичную запятую и пробел тысяч.

### Шаг 1. Декодируйте строго

```python
raw = path.read_bytes()
text = raw.decode("cp1251", errors="strict")
```

`strict` превращает неверную кодировку в наблюдаемую ошибку. Не используйте
`errors="ignore"` или `errors="replace"` в quality gate.

### Шаг 2. Сравните наивный и явный dialect

Парсер по умолчанию ожидает запятую:

```python
naive_header = next(csv.reader(io.StringIO(text)))
```

В учебном файле он видит один field. Явный delimiter восстанавливает шесть:

```python
reader = csv.DictReader(
    io.StringIO(text),
    delimiter=";",
    quotechar='"',
)
```

### Шаг 3. Проверьте ширину каждой строки

До создания словаря сравните фактическое число полей с заголовком:

```python
if len(row) != len(header):
    raise ValueError(
        f"line {reader.line_num}: expected {len(header)}, got {len(row)}"
    )
```

Номер строки и обе ширины важнее сообщения «CSV сломан»: они позволяют найти источник
дефекта, не удаляя наблюдение.

### Шаг 4. Примените числовой договор

Для `1 200,50` сначала проверьте форму токена, а уже потом удаляйте договорный разделитель:

```python
number = re.compile(r"[+-]?(?:[0-9]+|[0-9]{1,3}(?: [0-9]{3})+)(?:,[0-9]+)?")
if number.fullmatch(value) is None:
    raise ValueError(f"invalid decimal format: {value!r}")

normalized = value.replace(" ", "").replace(",", ".")
amount = Decimal(normalized)
if not amount.is_finite():
    raise ValueError(f"decimal must be finite: {value!r}")
```

Порядок принципиален. Если сразу удалить все пробелы, повреждённое `12 00,50` молча
станет правдоподобным `1200.50`. Это не универсальная очистка строк, а преобразование,
разрешённое конкретным контрактом после проверки его формы.

Запустите прозрачный пример:

```bash
uv run --locked python code/main.py
```

Он показывает, что наивное чтение видит один столбец, явное — шесть, quoted delimiter
остаётся внутри комментария, а сумма после договорного преобразования равна `3226.59`.

## Используйте это

pandas читает тот же файл только после фиксации структуры:

```python
frame = pd.read_csv(
    path,
    encoding="cp1251",
    sep=";",
    quotechar='"',
    dtype="string",
    keep_default_na=False,
    na_filter=False,
    on_bad_lines="error",
)
```

Первый проход намеренно сохраняет исходные токены как строки:

- `dtype="string"` откладывает типизацию;
- `keep_default_na=False` и `na_filter=False` не расширяют null policy;
- `on_bad_lines="error"` не разрешает молчаливую потерю строк;
- encoding и dialect не зависят от локали машины.

После структурного gate можно отдельно применить `null_values`, `decimal`, `thousands`,
timestamp parser и domain checks.

Самостоятельный аудитор выполняет оба слоя:

```bash
uv run --locked python outputs/csv_audit.py \
  --input ../data/tiny/orders_semicolon_cp1251.csv \
  --contract ../data/contract.json
```

JSON-отчёт содержит:

- размер и SHA-256 исходных байтов;
- объявленную кодировку и обнаруженный BOM;
- фактический и ожидаемый заголовок;
- malformed rows с номером строки и шириной;
- null и invalid counts по каждому столбцу;
- соблюдение явной timezone policy для timestamp;
- результат необязательной row-count policy `exact` или `min`;
- результат строгого чтения pandas;
- итоговый `valid` и число проваленных проверок.

Коды возврата:

- `0` — файл соответствует контракту;
- `1` — файл прочитан, но данные или структура нарушают контракт;
- `2` — файл или контракт нельзя проверить;
- `0` с `--allow-failures` — учебный просмотр известного дефекта.

## Сломайте это

Второй fixture содержит строку:

```text
O2002;U002;2026-05-02T08:30:00Z;950,00;RUB;скидка; май
```

Комментарий не заключён в кавычки, поэтому parser видит семь полей вместо шести.

```bash
uv run --locked python outputs/csv_audit.py \
  --input ../data/tiny/orders_broken_cp1251.csv \
  --contract ../data/contract.json \
  --allow-failures
```

Отчёт должен показать line `3`, expected fields `6` и actual fields `7`.

Проверьте другие failure modes:

1. замените encoding в копии контракта на `utf-8`;
2. удалите `currency` из заголовка;
3. запишите `not-a-number`, `12 00,50` или `NaN` в `amount`;
4. удалите UTC offset из `ordered_at`;
5. сделайте пустым non-null `order_id`;
6. поменяйте `NULL` на `N/A`, не меняя null policy;
7. добавьте шестую корректную строку сначала с `row_count.mode = "exact"`, а затем без
   `row_count`.

Каждый дефект должен менять конкретную проверку, а не приводить к неуправляемому
traceback.

## Проверьте это

## Поставьте результат

`outputs/csv_audit.py` — самостоятельный CLI для preflight-проверки внешнего CSV. Он
получает путь к файлу и JSON-контракт, не зависит от текста урока и подходит как локальный
gate перед pandas/DuckDB или как шаг CI.

Артефакт не исправляет данные автоматически. Его задача — доказать, какой договор
выполнен, и точно локализовать расхождение. Глобальная null policy и поддержанные типы
являются осознанной границей этого небольшого аудитора, а не заявкой на универсальный
schema registry.

## Ключевые термины

| Термин | Распространенное заблуждение | Точное значение |
|---|---|---|
| Encoding | Настройка pandas | Правило преобразования байтов в символы до CSV-парсинга |
| CSV dialect | Всегда запятая | Набор правил delimiter, quotechar и экранирования |
| Header | Первая строка с любыми словами | Объявленные имена и порядок полей |
| Null policy | Все похожие слова являются NA | Явный набор токенов отсутствующего значения |
| Type inference | Надёжное определение схемы | Эвристика по наблюдаемой выборке значений |
| Malformed row | Строка, которую можно пропустить | Запись, не соответствующая структурному контракту |

## Дополнительное чтение

- [Python: `csv`](https://docs.python.org/3/library/csv.html) — обязательное продолжение урока: прочитайте **Module Contents**, **Dialects and Formatting Parameters**, описание `Sniffer` и атрибут `line_num`. Сопоставьте `delimiter`, `quotechar`, `doublequote`, `skipinitialspace` и `strict` с JSON-контрактом урока и обратите внимание, что документация прямо называет `Sniffer` грубой эвристикой.
- [pandas: `read_csv`](https://pandas.pydata.org/docs/reference/api/pandas.read_csv.html) — разберите параметры `dtype`, `na_values`, `keep_default_na`, `na_filter`, `decimal`, `thousands`, `encoding_errors` и `on_bad_lines`. Затем для каждого параметра в примере урока сформулируйте, какую часть контракта он реализует и почему первичное чтение оставляет все токены строками.
- [Microsoft Learn: соединитель Power Query Text/CSV](https://learn.microsoft.com/ru-ru/power-query/connectors/text-csv) — в русскоязычной официальной документации прочитайте разделы **Разделители текста и CSV** и **Устранение неполадок**, особенно обнаружение типов по первым 200 строкам, всему файлу или его отключение. Это переносит проблему parser inference из Python в знакомые Excel и Power BI и показывает, как зафиксированное число столбцов влияет на последующие обновления.
- [Python: `codecs`](https://docs.python.org/3/library/codecs.html#error-handlers) — изучите раздел **Error Handlers** и сравните `strict`, `ignore` и `replace`. Материал объясняет, почему успешное декодирование не тождественно сохранности данных и почему replacement character должен считаться наблюдаемым дефектом, а не исправлением.
- [Python: `decimal`](https://docs.python.org/3/library/decimal.html#decimal.Decimal.is_finite) — начните с **Quick-start tutorial**, затем найдите грамматику строк конструктора `Decimal` и метод `is_finite()`. Документация показывает, что `NaN` и `Infinity` являются допустимыми объектами `Decimal`, поэтому контракт денежного столбца обязан отдельно проверять форму токена и конечность значения.
- [Python: `datetime`](https://docs.python.org/3/library/datetime.html#aware-and-naive-objects) — прочитайте **Aware and naive objects** и примеры `datetime.fromisoformat()`. Сравните результаты для строки без offset, с `Z` и с `+03:00`: сам parser принимает и naive-, и aware-время, а требование однозначного момента остаётся ответственностью контракта источника.
- [Postgres Pro: команда `COPY`](https://postgrespro.ru/docs/postgrespro/current/sql-copy) — в русскоязычном разделе **Формат CSV** разберите `DELIMITER`, `QUOTE`, `NULL`, `FORCE_NULL` и `FORCE_NOT_NULL`, а также ошибки разной ширины записей. Особенно полезно сравнение пустой строки и SQL `NULL`: оно показывает реальную поколоночную политику, которая сознательно не реализована в небольшом аудиторе урока.
- [RFC 4180: Common Format and MIME Type for CSV Files](https://www.rfc-editor.org/rfc/rfc4180.html) — прочитайте разделы **2. Definition of the CSV Format** и **3. MIME Type Registration**. Используйте документ как распространённую точку совместимости для заголовка, одинаковой ширины и quoting, но не как доказательство, что любой файл с расширением `.csv` обязан следовать одному диалекту.
- [Yandex Cloud: передача данных из эндпоинта-источника S3](https://yandex.cloud/ru/docs/data-transfer/operations/endpoint/source/s3) — в разделе **Настройки** найдите JSON-схему и параметры CSV: delimiter, quote, escape, encoding, double quote и переносы строк внутри значений. Страница показывает, что те же решения становятся явной конфигурацией промышленного ingestion-инструмента, а не остаются деталями `pd.read_csv`.
- [W3C: Model for Tabular Data and Metadata on the Web](https://www.w3.org/TR/tabular-data-model/) — для углубления прочитайте **6.4 Parsing Cells**, **7. Best Practice CSV** и начало **8. Parsing Tabular Data**. Модель связывает исходную строку, datatype, `null`, `required`, dialect и validation errors и показывает, как учебный JSON-контракт можно развить до переносимых метаданных без попытки угадывать смысл файла.
