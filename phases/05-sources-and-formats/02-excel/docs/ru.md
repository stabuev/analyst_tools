# Excel как источник: листы, диапазоны и формулы

> Excel-книга — интерфейс для человека. Таблица внутри неё становится источником данных
> только после явного и проверяемого контракта.

**Тип:** Case  
**Треки:** Core  
**Пререквизиты:** 05/01  
**Время:** ~60 минут  
**Результат:** выбирает лист и диапазон, распознает служебное оформление и преобразует
рабочую книгу в явную табличную схему.

## Цели обучения

- Отличать книгу, лист и извлекаемый табличный диапазон.
- Проверять границу таблицы, а не молча обрезать новые строки.
- Обнаруживать merged cells, hidden rows и hidden columns внутри данных.
- Разделять текст формулы и сохранённое вычисленное значение.
- Проверять типы, ключ и смысл локального времени до работы в pandas.

## Как этот урок продолжает маршрут

В `05/01` вы уже разделили четыре договора CSV: encoding, dialect, null policy и schema.
Вы также проверяли структуру до преобразования типов и отличали фиксированную поставку с
точным числом строк от меняющегося источника.

В Excel эти решения не исчезают, но перед ними появляется ещё один слой:

```text
workbook -> нужный sheet -> граница таблицы -> схема ячеек -> DataFrame
```

Расширение `.xlsx` не отвечает на вопросы:

- какой лист содержит данные;
- где заканчивается таблица;
- скрыта ли часть строк или столбцов;
- является ли значение константой или результатом формулы;
- какой часовой пояс подразумевал автор локальной даты.

Здесь вы научитесь извлекать из человеческого документа одну объявленную таблицу. В
`05/03` тот же принцип переносится на JSON: вместо workbook, sheet и range появятся
документ, пути и массивы с разным grain.

## Проблема

Финансовый отчёт открывается титульным листом. Заказы находятся на листе `Заказы`,
заголовок начинается со строки 4, справа расположен вычисляемый столбец `line_total`.
Первая автоматизация выглядит правдоподобно:

```python
frame = pd.read_excel("orders_report.xlsx", sheet_name="Заказы", header=3, nrows=5)
```

Она вернёт пять строк даже после нескольких опасных изменений:

1. поставщик добавил шестой заказ ниже выбранного диапазона;
2. одну строку скрыл фильтром или вручную;
3. в `amount` появилась строка `oops`;
4. формулу включили в таблицу, но книгу не пересчитали перед сохранением.

Получившийся DataFrame не обязательно упадёт. Он может выглядеть обычным и дать
правдоподобную, но неполную сумму. Поэтому успешное чтение — ещё не доказательство
корректного извлечения.

## Концепция

### 1. Книга — контейнер, range — договор

Workbook может содержать служебные листы, справочники, графики и несколько таблиц.
Активный или первый лист — свойство интерфейса, а не контракт данных.

В этом уроке поддерживается один намеренно простой режим границы:
`fixed_range`. Диапазон `A4:F9` означает:

- строка 4 — header;
- строки 5–9 — ровно пять записей;
- столбцы A–F — вся таблица;
- непустые ячейки A–F ниже строки 9 означают, что фиксированная поставка изменилась.

Проверка хвоста нужна потому, что `nrows=5` сама по себе всегда обрежет шестую строку.
Для регулярного источника с меняющимся объёмом фиксированный A1-range — неверный
контракт. Попросите поставщика оформить данные как именованную Excel Table либо
используйте отдельный loader с явно определённой динамической границей. Этот урок не
угадывает конец таблицы по форматированию.

### 2. Схема описывает значения, а не только названия

Порядок заголовков — лишь первая часть схемы. Для каждой колонки спецификация объявляет:

- тип;
- допустимость пустого значения;
- для локальной даты — исходный часовой пояс.

Кроме того, `key: ["order_id"]` требует непустые уникальные идентификаторы. Иначе пять
строк могут представлять только четыре заказа.

Поддерживаемые учебным аудитором типы ограничены задачей:

| Тип | Что считается допустимым |
|---|---|
| `string` | строковая ячейка |
| `integer` | целое число, но не `True`/`False` |
| `number` | конечное целое или вещественное число |
| `local_datetime` | Excel datetime без встроенного UTC offset |

`local_datetime` — показание местных часов, а не однозначный момент времени. Поле
`source_timezone: "Europe/Moscow"` фиксирует договор с поставщиком. Оно не доказывает
зону задним числом: если зона неизвестна, поставку нужно уточнить, а не назначать UTC.

### 3. Оформление может менять наблюдаемые данные

Merged cell хранит значение только в верхней левой ячейке. Hidden row или hidden column
остаётся в файле, но человек может не увидеть её при ручной сверке. Поэтому политика
`forbid_in_range` запрещает внутри машинной таблицы:

- объединённые ячейки;
- скрытые строки;
- скрытые столбцы.

Оформление вне range только попадает в отчёт. Например, merged-заголовок `A1:G1` и
скрытый служебный столбец `H` не делают диапазон `A4:F9` невалидным.

### 4. У формулы есть два разных представления

```python
formula_book = load_workbook(path, data_only=False)
cached_book = load_workbook(path, data_only=True)
```

В первом представлении `G5` содержит текст `=D5*F5`. Во втором openpyxl возвращает
последнее значение, сохранённое расчётным приложением. Сам openpyxl формулу не вычисляет.

Отсюда две безопасные политики урока:

| Политика | Условие приёмки |
|---|---|
| `forbid_in_range` | внутри таблицы нет формул |
| `allow_with_cached_value` | у каждой формулы есть сохранённое значение |

Наличие cached value не гарантирует свежесть расчёта. Оно лишь исключает книгу, из
которой Python вообще не может получить результат. Если свежесть формулы критична,
поставщик должен пересчитать книгу в доверенном приложении и зафиксировать этот шаг в
процессе поставки.

## Соберите это

### Шаг 1. Посмотрите на структуру до pandas

```python
from openpyxl import load_workbook

formula_book = load_workbook(path, data_only=False)
cached_book = load_workbook(path, data_only=True)

print(formula_book.sheetnames)
sheet = formula_book["Заказы"]
print(sheet["G5"].value)
print(cached_book["Заказы"]["G5"].value)
```

На учебной книге вы увидите формулу `=D5*F5` и `None` вместо cached result. Это
наблюдаемый аргумент не включать G в поставку при текущем договоре.

### Шаг 2. Проверьте границу

`range_boundaries("A4:F9")` переводит A1-нотацию в номера крайних строк и столбцов.
После чтения прямоугольника отдельно просмотрите те же столбцы ниже `max_row`:

```python
spill_rows = [
    row
    for row in range(max_row + 1, sheet.max_row + 1)
    if any(
        sheet.cell(row=row, column=column).value is not None
        for column in range(min_col, max_col + 1)
    )
]
```

Непустой `spill_rows` не нужно автоматически присоединять. Это сигнал изменения
договора: новая строка может быть заказом, итогом или примечанием.

### Шаг 3. Проверьте значения

Сопоставьте каждую ячейку с правилом её колонки и сохраните номера проблемных Excel-строк.
Проверяйте `order_id` как ключ отдельно от типа: две корректные строки могут содержать
одинаковый идентификатор.

Запустите прозрачный пример:

```bash
uv run --locked python code/main.py
```

Он показывает выбранный лист и диапазон, обе стороны формулы, служебное оформление,
границу и только затем результат pandas.

## Используйте это

Полный договор находится в `../data/excel_spec.json`. Его центральная часть выглядит
так:

```json
{
  "boundary": {
    "mode": "fixed_range",
    "range": "A4:F9",
    "reject_nonempty_below": true
  },
  "columns": {
    "order_id": {"type": "string", "nullable": false},
    "ordered_at": {
      "type": "local_datetime",
      "nullable": false,
      "source_timezone": "Europe/Moscow"
    },
    "amount": {"type": "number", "nullable": false}
  },
  "key": ["order_id"],
  "formula_policy": "forbid_in_range",
  "layout_policy": "forbid_in_range"
}
```

Запустите самостоятельный аудитор из каталога урока:

```bash
uv run --locked python outputs/excel_audit.py \
  --input ../data/tiny/orders_report.xlsx \
  --spec ../data/excel_spec.json
```

Только после успешного preflight pandas получает те же координаты:

```python
frame = pd.read_excel(
    path,
    sheet_name="Заказы",
    header=3,
    usecols="A:F",
    nrows=5,
    dtype=object,
    engine="openpyxl",
    keep_default_na=False,
)
```

`header=3` использует нулевую индексацию и соответствует строке Excel 4. `dtype=object`
не заменяет проверку схемы: оно лишь не разрешает pandas молча выбрать разные dtype для
разных поставок.

### Получите правдоподобный неверный DataFrame

Behavioral tests создают временные копии книги и независимо меняют:

- шестую строку сразу под range;
- видимость строки 6;
- `D5` с числа на строку;
- `A6` на повторный `order_id`;
- policy и range так, чтобы включить формулы без cached values.

Каждый файл по-прежнему открывается как `.xlsx`. Quality gate обязан отклонить его по
причине, связанной с изменением, а не просто завершиться исключением.

## Проверьте это

Контрольные инварианты:

- явно выбран лист `Заказы`, а не активный лист;
- header полностью и в нужном порядке совпадает со схемой;
- ниже фиксированного диапазона нет непредусмотренных записей;
- внутри range нет скрытых или merged ячеек;
- типы и nullability проверены по каждой колонке;
- `order_id` непуст и уникален;
- naive `ordered_at` получает смысл только вместе с `Europe/Moscow`;
- политика формул проверяет либо отсутствие формул, либо наличие cached values;
- pandas читает тот же sheet, header, usecols и row boundary.

```bash
uv run --locked python -m unittest discover -s tests
```

## Поставьте результат

`outputs/excel_audit.py` принимает произвольные пути к книге и спецификации и выпускает
JSON с checksum файла, структурой workbook, результатами selection, formulas, schema и
pandas preview.

Коды завершения образуют пригодный для автоматизации интерфейс:

| Код | Значение |
|---:|---|
| `0` | все проверки пройдены |
| `1` | книга прочитана, но нарушает контракт |
| `2` | книгу или спецификацию нельзя проверить |

`--allow-failures` оставляет код `0` для учебного просмотра невалидного отчёта. В
production gate этот флаг не используют.

## Границы урока

Здесь сознательно не рассматриваются:

- выполнение Excel как расчётного движка;
- VBA-макросы и сохранение `.xlsm`;
- зашифрованные книги и старый бинарный формат `.xls`;
- pivot tables, графики и полный каталог стилей;
- универсальное угадывание динамической области данных.

Эти задачи требуют отдельной модели угроз и поставки. Аудитор урока решает более узкую
задачу: безопасно выделить одну известную таблицу из обычного `.xlsx`.

## Ключевые термины

| Термин | Распространённое заблуждение | Точное значение |
|---|---|---|
| Workbook | Одна таблица | Контейнер листов, свойств, формул и оформления |
| Sheet | Всегда данные | Отдельная поверхность книги, в том числе служебная |
| Fixed range | Любые пять строк | Объявленный прямоугольник с проверяемой границей |
| Spill row | Строка, которую можно отбросить | Непредусмотренная запись ниже границы |
| Local datetime | Готовый UTC timestamp | Показание часов, которому ещё нужна объявленная зона |
| Cached value | Результат openpyxl | Последний результат формулы, сохранённый другим приложением |
