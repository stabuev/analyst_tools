Method chaining и читаемые пайплайны

Pipeline надёжен не потому, что помещается в одну цепочку. Он надёжен, когда порядок стадий виден, каждая стадия сохраняет свой контракт, а ошибка останавливает расчёт там, где впервые возникла.

Тип: Build Треки: Core Пререквизиты: 03/10 Время: ~75 минут Результат: собирает уже проверенные преобразования в чистый pandas pipeline через именованные стадии, assign и pipe, размещает checkpoints на границах контрактов и сохраняет промежуточный результат, когда он нужен для диагностики.

Цели обучения

После урока вы сможете:

  • объяснить pipeline как порядок преобразований и проверок, а не как длинное выражение;
  • описать контракт стадии: что она ожидает, что меняет и что обязана сохранить;
  • сначала скомпоновать стадии обычными переменными, а затем перенести тот же порядок в DataFrame.pipe;
  • использовать assign для связанных производных столбцов внутри одной стадии;
  • строить pass-through checkpoint, который проверяет таблицу и возвращает её дальше без изменения;
  • выбрать между продолжением цепочки и именованным промежуточным результатом;
  • сохранить строгие правила dtype, пропусков, времени и категорий при композиции;
  • проверить порядок отказов, отсутствие мутации и инварианты промежуточных таблиц.

Проблема

В orders.csv один и тот же подтверждённый статус записан тремя способами:

order_id сырое status amount
O1001 paid 1200.00
O1003 paid 5500.00
O1007 PAID 75.50

Если сначала вычислить признак оплаты, а нормализовать строки позже, код выглядит разумно:

python
wrong = orders.assign(
    is_paid=orders["status"].eq("paid"),
    paid_amount=orders["amount"].where(
        orders["status"].eq("paid"),
        0,
    ),
)

Но O1003 и O1007 станут неоплаченными. Ошибка не вызовет исключение: сумма выручки просто окажется правдоподобно заниженной.

Обратный порядок решает только часть проблемы:

text
нормализовать status
-> проверить стабильный словарь
-> строго разобрать amount
-> только затем вычислить paid_amount

Если между этими шагами нет явных границ, внутри длинной цепочки легко потерять ещё три контракта:

  • amount="oops" после безусловного errors="coerce" станет пропуском;
  • timestamp без offset после нестрогого разбора может быть принят за UTC;
  • новый статус completed после сравнения с paid станет обычным False.

Во всех трёх случаях pipeline завершится и отдаст число. Поэтому нам нужна не просто цепочка методов, а проверяемая последовательность стадий.

Концепция

Pipeline — это порядок стадий

В этом уроке pipeline — обычная последовательность функций:

text
входная таблица
-> проверка raw-контракта
-> нормализация и типизация
-> checkpoint нормализованной таблицы
-> перевод времени
-> расчёт производных полей
-> checkpoint результата
-> воспроизводимая сортировка

Каждая стрелка передаёт таблицу следующей стадии. Запись через pipe лишь делает эту передачу компактной. Она не исправляет неверный порядок и не добавляет проверок сама.

Стадия отвечает за один уровень решения

Стадия — именованная функция DataFrame -> DataFrame с понятной ответственностью.

Стадия Что ожидает Что меняет Что сохраняет
check_raw_orders обязательные столбцы и один заказ на строку ничего все строки, столбцы и индекс
normalize_order_fields сырые status, currency и amount текст, dtype и словарь status grain и индекс
check_normalized_orders объявленные dtype и словарь ничего весь вход без изменений
add_time_columns timestamp с явным offset добавляет UTC и локальную дату строки, grain и индекс
add_paid_metrics проверенные status и amount добавляет is_paid, paid_amount строки, grain и индекс
check_prepared_orders все производные столбцы ничего весь вход без изменений

Название normalize_everything было бы слабым: из него невозможно понять, где искать ошибку status, amount или времени. Но дробить каждое выражение на отдельную функцию тоже не нужно. Граница полезна, если у шага есть собственный входной контракт, отдельный failure mode или самостоятельная проверка.

Что означает «чистая стадия» в этом курсе

Для pandas-пайплайна нам достаточно практического контракта:

  • все входы передаются аргументами;
  • функция не читает файл и не обращается к глобальному изменяемому состоянию;
  • исходный DataFrame не мутирует;
  • одинаковый вход и параметры дают одинаковый результат;
  • нарушение контракта вызывает предметную ошибку;
  • функция либо возвращает новый DataFrame, либо проверяет и возвращает тот же объект без изменения.

Это не обещание, что pandas никогда не использует внутренние копии или оптимизации. Это наблюдаемое правило для вызывающего кода: после вызова источник остаётся прежним, а результат можно тестировать отдельно.

Checkpoint — это проходная проверка

Checkpoint не обязан сохранять CSV. В нашем pipeline это функция вида:

python
def check_something(frame: pd.DataFrame) -> pd.DataFrame:
    if contract_is_broken(frame):
        raise PipelineContractError("check_something: ...")
    return frame

Если контракт выполнен, функция возвращает таблицу дальше. Если нет — pipeline останавливается на ближайшей осмысленной границе.

Хорошее имя ошибки содержит стадию:

text
normalize_order_fields: unknown status values: ['completed']

По нему видно не только что сломалось, но и какая часть данных уже была обработана.

assign, pipe и промежуточная переменная решают разные задачи

Инструмент Когда использовать Когда не использовать
assign добавить несколько связанных столбцов на том же grain спрятать нормализацию, join и проверку в одном callback
pipe передать таблицу именованной предметной функции превратить каждую простую операцию в отдельную функцию
обычный метод короткая очевидная операция вроде финальной сортировки скрыть доменное правило в длинном выражении
переменная результат нужно посмотреть, сравнить, закешировать или передать коллеге единственная цель — искусственно избежать любой цепочки

Читаемость не измеряется минимальным числом строк. Если нормализованную таблицу нужно диагностировать, хорошее решение — дать ей имя.

Порядок стадий является частью контракта

Две функции могут быть корректны по отдельности, но давать неверный процесс в обратном порядке:

text
normalize status -> validate vocabulary -> calculate paid metrics  # корректно
calculate paid metrics -> normalize status                         # неверно

Поэтому тесты pipeline проверяют не только функции, но и ошибки, которые должны быть пойманы до необратимого расчёта.

Соберите это

Сначала соберём процесс обычными присваиваниями. Так промежуточные состояния остаются видимыми, а механизм композиции не скрывается за pipe.

Шаг 1. Загрузите учебную таблицу

Из корня репозитория:

python
from pathlib import Path

import pandas as pd

DATA = Path("phases/03-pandas/data/tiny/orders.csv")
orders = pd.read_csv(DATA)

До преобразований сформулируйте grain:

text
одна строка -> один заказ
кандидатный бизнес-ключ -> order_id
строк ожидается после сохраняющих стадий -> столько же, сколько во входе

Шаг 2. Зафиксируйте карточки стадий

Не начинайте с синтаксиса цепочки. Для каждой стадии ответьте на четыре вопроса:

text
1. Какие столбцы и dtype она ожидает?
2. Что именно она добавляет или изменяет?
3. Должны ли сохраниться строки, grain и индекс?
4. Какая ошибка обязана остановить процесс здесь?

Для normalize_order_fields карточка выглядит так:

text
вход:  raw status, currency, amount
выход: categorical status, string currency, Float64 amount
сохраняет: число строк, order_id, индекс
останавливает: missing/unknown status, неверный код currency,
              непустой неразбираемый amount

Эта запись важнее .pipe(...): она определяет смысл стадии независимо от формы вызова.

Шаг 3. Соберите последовательность обычными переменными

Загрузите функции из своего рабочего файла. Ниже важен интерфейс функций, а не имя модуля:

python
from order_pipeline import (
    add_paid_metrics,
    add_time_columns,
    check_normalized_orders,
    check_prepared_orders,
    check_raw_orders,
    normalize_order_fields,
)

Готовый reference-артефакт запускается через code/main.py; там загрузка файла из папки урока уже настроена.

Теперь соедините стадии без method chaining:

python
source = orders.copy(deep=True)
source_index = source.index.copy()
source_rows = len(source)

raw_checked = check_raw_orders(source)
normalized = normalize_order_fields(raw_checked)
normalized_checked = check_normalized_orders(
    normalized,
    expected_index=source_index,
)
with_time = add_time_columns(
    normalized_checked,
    timezone="Europe/Moscow",
)
with_metrics = add_paid_metrics(with_time)
prepared = check_prepared_orders(
    with_metrics,
    expected_index=source_index,
    expected_rows=source_rows,
)
result = (
    prepared
    .sort_values("order_id", kind="stable")
    .reset_index(drop=True)
)

Это уже pipeline. Method chaining пока не используется, но:

  • порядок стадий явный;
  • результат каждой стадии можно открыть;
  • каждая функция получает результат предыдущей;
  • checkpoints находятся рядом с контрактами;
  • финальная сортировка отделена от сохраняющих стадий.

Шаг 4. Посмотрите на границу, а не только на финал

Например, после normalize_order_fields проверьте:

python
assert normalized.index.equals(source_index)
assert len(normalized) == source_rows
assert str(normalized["amount"].dtype) == "Float64"
assert normalized["status"].cat.categories.tolist() == [
    "paid",
    "refunded",
    "pending",
    "cancelled",
]

Если эта таблица нужна для диагностики, переменная normalized полезна и в рабочем коде. Не нужно удалять её только ради визуально непрерывной цепочки.

Шаг 5. Предскажите отказ до запуска

Для каждого входа назовите стадию, которая должна остановить процесс:

Изменение Ожидаемая стадия отказа Почему нельзя продолжать
повтор order_id check_raw_orders grain нарушен до расчётов
amount="oops" normalize_order_fields invalid нельзя превращать в missing
status="completed" normalize_order_fields unknown нельзя считать False
timestamp без offset add_time_columns неизвестно, где находится момент на UTC timeline
paid-заказ без amount check_prepared_orders выручка для оплаченного заказа неизвестна

Такое предсказание превращает pipeline из набора вызовов в проверяемую модель процесса.

Используйте это

Теперь заменим только способ передачи таблицы между теми же функциями.

pipe передаёт текущий DataFrame первым аргументом

Reference-функция prepare_orders содержит:

python
def prepare_orders(frame: pd.DataFrame, *, timezone: str) -> pd.DataFrame:
    source = frame.copy(deep=True)
    source_index = source.index.copy()
    source_rows = len(source)

    return (
        source.pipe(check_raw_orders)
        .pipe(normalize_order_fields)
        .pipe(
            check_normalized_orders,
            expected_index=source_index,
        )
        .pipe(add_time_columns, timezone=timezone)
        .pipe(add_paid_metrics)
        .pipe(
            check_prepared_orders,
            expected_index=source_index,
            expected_rows=source_rows,
        )
        .sort_values("order_id", kind="stable")
        .reset_index(drop=True)
    )

Вызов:

python
frame.pipe(add_time_columns, timezone="Europe/Moscow")

эквивалентен:

python
add_time_columns(frame, timezone="Europe/Moscow")

pipe не меняет поведение функции. Он делает направление потока данных видимым сверху вниз и позволяет читать pipeline как список предметных стадий.

assign остаётся внутри стадии

Временная стадия сначала строго разбирает timestamp, проверяет offset и только потом добавляет связанные столбцы:

python
return frame.assign(
    ordered_at_utc=parsed,
    local_order_date=local.dt.date,
)

assign возвращает новый DataFrame, поэтому вызывающий код не получает скрытую мутацию. Выражения вычисляются по порядку объявления; более поздний callable может использовать столбец, созданный выше в том же assign. Но длинную цепочку зависимых вычислений лучше разделить, если отдельный результат имеет собственный контракт.

Простые методы не обязаны становиться стадиями

Финальные:

python
.sort_values("order_id", kind="stable")
.reset_index(drop=True)

остаются обычными методами. Их эффект короток и понятен: задать воспроизводимый порядок и создать технический индекс результата. Функция sort_and_reset_everything не добавила бы предметного смысла.

Когда цепочку нужно разорвать

Сохраните промежуточный результат в переменную, если нужно:

  • посмотреть распределение после нормализации;
  • сравнить таблицу до и после merge;
  • сохранить evidence для handoff;
  • повторно использовать дорогой результат;
  • передать таблицу в две разные ветки анализа;
  • локализовать ошибку, которую одного сообщения недостаточно объяснить.

Например:

python
normalized = (
    source.pipe(check_raw_orders)
    .pipe(normalize_order_fields)
    .pipe(check_normalized_orders, expected_index=source.index)
)

inspect_status_distribution(normalized)

result = (
    normalized.pipe(add_time_columns, timezone="Europe/Moscow")
    .pipe(add_paid_metrics)
)

Это не менее «правильный» pipeline. Переменная обозначает важную границу процесса.

Почему в обязательном маршруте нет query

DataFrame.query может быть удобен для некоторых фильтров, но он не решает новую задачу композиции. У него отдельный язык строковых выражений и собственные правила обращения к внешним переменным. В 03/03 уже изучены обычные и nullable-маски, где индекс и политика NA видны напрямую.

Поэтому в этом уроке фильтрация остаётся через знакомые маски, а query не является скрытым prerequisite. При необходимости его можно изучить как дополнительный интерфейс, не меняя модель pipeline.

Сломайте это

1. Рассчитайте метрику до нормализации status

python
broken = orders.assign(
    is_paid=lambda value: value["status"].eq("paid"),
)

Код не падает, но пропускает " paid " и "PAID". Это опаснее явного исключения: неверный ответ выглядит реалистично.

2. Превратите invalid amount в missing

python
amount = pd.to_numeric(orders["amount"], errors="coerce")

errors="coerce" допустим как часть аудита, если после него сравниваются исходная непустота и результат разбора. Без такой проверки "oops" становится неотличимым от настоящего пропуска. Pipeline должен остановиться на normalize_order_fields.

3. Примите naive timestamp за UTC

python
pd.to_datetime(
    pd.Series(["2026-02-01 10:00:00"]),
    utc=True,
)

Параметр utc=True не сообщает исходный часовой пояс. Строка без Z или +03:00 нарушает контракт 03/09 и должна быть отклонена во временной стадии.

4. Посчитайте unknown status как False

python
pd.Series(["completed"], dtype="string").eq("paid")

Результат False технически верен для сравнения строк, но предметно ещё неизвестно, что означает новый статус. Сначала нужно сверить стабильный словарь, затем считать метрику.

5. Измените вход inplace

python
def bad_stage(frame):
    frame["status"] = frame["status"].str.strip().str.lower()
    return frame

После вызова исходный notebook-объект уже изменён. Повторный запуск ячейки работает на другом входе, а тесты зависят от порядка. Верхнеуровневая функция копирует источник, а преобразующие стадии используют assign.

6. Незаметно переставьте строки внутри сохраняющей стадии

Функция может не удалить строки, но изменить порядок или метки индекса. Следующая операция с внешней Series выровняет значения по меткам, а не по видимой позиции. check_normalized_orders поэтому сверяет весь индекс, а не только len(frame).

7. Спрячьте несколько уровней абстракции в одной функции

text
clean_and_join_and_group_and_export(...)

Такую функцию трудно проверить на границах. Нормализация, смена grain, join и I/O имеют разные контракты и failure modes; им нужны отдельные стадии.

Проверьте это

Карта инвариантов

Граница Что должно быть истинно
после check_raw_orders обязательные столбцы; order_id заполнен и уникален
после normalize_order_fields status из стабильного словаря; currency — string; amount — Float64
после check_normalized_orders индекс и порядок строк совпадают с источником
после add_time_columns непустые timestamps имели offset и находятся на UTC timeline
после add_paid_metrics метрика рассчитана только из проверенного status
после check_prepared_orders paid сохраняет amount; non-paid даёт 0; paid без amount запрещён
после сортировки порядок воспроизводим; технический индекс создан заново

Важно: финальная проверка не заменяет промежуточные. Если invalid amount обнаружить лишь после расчёта выручки, часть информации об источнике уже потеряна.

01

Стадия нормализации обязана сохранять строки, но случайно переставила их. Какая проверка лучше всего локализует ошибку?

После нормализации нужно изучить распределение status и только затем продолжить расчёт. Как сохранить читаемость pipeline?

Именованный промежуточный результат обозначает диагностическую границу. Читаемость не требует одной непрерывной цепочки.

03

Как должен вести себя pass-through checkpoint внутри DataFrame.pipe?

Checkpoint проверяет контракт границы. Возврат таблицы позволяет продолжить pipe, а исключение не даёт ошибке распространиться в последующие расчёты.

from __future__ import annotations

import pandas as pd
from pandas.api.types import CategoricalDtype

REQUIRED_COLUMNS = {"order_id", "ordered_at", "status", "currency", "amount"}
STATUS_CATEGORIES = ["paid", "refunded", "pending", "cancelled"]
STATUS_DTYPE = CategoricalDtype(categories=STATUS_CATEGORIES, ordered=False)
EXPLICIT_OFFSET_PATTERN = r"(?:Z|[+-]\d{2}:\d{2})$"


class PipelineContractError(ValueError):
    """Raised when a named pipeline stage breaks its declared contract."""


def _require_columns(frame: pd.DataFrame, *, stage: str) -> None:
    missing = sorted(REQUIRED_COLUMNS - set(frame.columns))
    if missing:
        raise PipelineContractError(f"{stage}: missing columns: {missing}")


def _examples(series: pd.Series, mask: pd.Series) -> list[str]:
    values = series.loc[mask].astype("string").dropna().unique().tolist()
    return [str(value) for value in values[:5]]


def _normalize_text(series: pd.Series) -> pd.Series:
    normalized = (
        series.astype("string")
        .str.normalize("NFKC")
        .str.strip()
        .str.casefold()
    )
    return normalized.mask(normalized.eq("").fillna(False), pd.NA)


def check_raw_orders(frame: pd.DataFrame) -> pd.DataFrame:
    """Check the incoming schema and order grain without changing the frame."""

    if not isinstance(frame, pd.DataFrame):
        raise PipelineContractError("check_raw_orders: expected a pandas DataFrame")
    _require_columns(frame, stage="check_raw_orders")

    order_id = frame["order_id"].astype("string").str.strip()
    missing_key = order_id.isna() | order_id.eq("").fillna(False)
    if missing_key.any():
        raise PipelineContractError(
            "check_raw_orders: order_id must be non-missing and non-blank"
        )
    if order_id.duplicated().any():
        duplicates = _examples(order_id, order_id.duplicated(keep=False))
        raise PipelineContractError(
            f"check_raw_orders: expected one row per order_id; duplicates: {duplicates}"
        )
    return frame


def normalize_order_fields(frame: pd.DataFrame) -> pd.DataFrame:
    """Normalize text and parse amount without confusing invalid values with missing."""

    _require_columns(frame, stage="normalize_order_fields")

    status = _normalize_text(frame["status"])
    if status.isna().any():
        raise PipelineContractError(
            "normalize_order_fields: status must be non-missing and non-blank"
        )
    unknown_status = ~status.isin(STATUS_CATEGORIES)
    if unknown_status.any():
        unknown = _examples(status, unknown_status)
        raise PipelineContractError(
            f"normalize_order_fields: unknown status values: {unknown}"
        )

    currency = (
        frame["currency"]
        .astype("string")
        .str.normalize("NFKC")
        .str.strip()
        .str.upper()
    )
    currency = currency.mask(currency.eq("").fillna(False), pd.NA)
    if currency.isna().any():
        raise PipelineContractError(
            "normalize_order_fields: currency must be non-missing and non-blank"
        )
    invalid_currency = ~currency.str.fullmatch(r"[A-Z]{3}", na=False)
    if invalid_currency.any():
        invalid = _examples(currency, invalid_currency)
        raise PipelineContractError(
            f"normalize_order_fields: invalid currency codes: {invalid}"
        )

    amount_source = frame["amount"].astype("string").str.strip()
    amount_missing = amount_source.isna() | amount_source.eq("").fillna(False)
    amount = pd.to_numeric(
        amount_source.mask(amount_missing),
        errors="coerce",
    )
    invalid_amount = (~amount_missing & amount.isna()) | amount.isin(
        [float("inf"), float("-inf")]
    )
    if invalid_amount.any():
        invalid = _examples(amount_source, invalid_amount)
        raise PipelineContractError(
            f"normalize_order_fields: invalid amount values: {invalid}"
        )

    return frame.assign(
        status=status.astype(STATUS_DTYPE),
        currency=currency.astype("string"),
        amount=amount.astype("Float64"),
    )


def check_normalized_orders(
    frame: pd.DataFrame,
    *,
    expected_index: pd.Index,
) -> pd.DataFrame:
    """Checkpoint the text, dtype, vocabulary, and row-identity contracts."""

    if not frame.index.equals(expected_index):
        raise PipelineContractError(
            "check_normalized_orders: stage changed row labels or their order"
        )
    if str(frame["amount"].dtype) != "Float64":
        raise PipelineContractError(
            "check_normalized_orders: amount must have nullable Float64 dtype"
        )
    if frame["status"].dtype != STATUS_DTYPE:
        raise PipelineContractError(
            "check_normalized_orders: status vocabulary or category order changed"
        )
    if str(frame["currency"].dtype) != "string":
        raise PipelineContractError(
            "check_normalized_orders: currency must have string dtype"
        )
    return frame


def add_time_columns(
    frame: pd.DataFrame,
    *,
    timezone: str,
) -> pd.DataFrame:
    """Parse aware timestamps onto UTC and derive the local business date."""

    source = frame["ordered_at"].astype("string").str.strip()
    missing = source.isna() | source.eq("").fillna(False)
    parsed = pd.to_datetime(
        source.mask(missing),
        format="ISO8601",
        errors="coerce",
        utc=True,
    )
    invalid = ~missing & parsed.isna()
    if invalid.any():
        values = _examples(source, invalid)
        raise PipelineContractError(
            f"add_time_columns: invalid ordered_at values: {values}"
        )

    has_offset = source.str.contains(
        EXPLICIT_OFFSET_PATTERN,
        regex=True,
        na=False,
    )
    naive = ~missing & ~has_offset
    if naive.any():
        values = _examples(source, naive)
        raise PipelineContractError(
            f"add_time_columns: timestamps need an explicit UTC offset: {values}"
        )

    try:
        local = parsed.dt.tz_convert(timezone)
    except (TypeError, ValueError, KeyError) as error:
        raise PipelineContractError(
            f"add_time_columns: invalid timezone: {timezone}"
        ) from error

    return frame.assign(
        ordered_at_utc=parsed,
        local_order_date=local.dt.date,
    )


def add_paid_metrics(frame: pd.DataFrame) -> pd.DataFrame:
    """Add paid flags and amounts after status and amount contracts are satisfied."""

    if frame["status"].isna().any():
        raise PipelineContractError(
            "add_paid_metrics: status must be known before calculating paid metrics"
        )
    is_paid = frame["status"].eq("paid").astype("boolean")
    return frame.assign(
        is_paid=is_paid,
        paid_amount=frame["amount"].where(is_paid, 0).astype("Float64"),
    )


def check_prepared_orders(
    frame: pd.DataFrame,
    *,
    expected_index: pd.Index,
    expected_rows: int,
) -> pd.DataFrame:
    """Check final grain, row identity, and paid-metric invariants."""

    if len(frame) != expected_rows or not frame.index.equals(expected_index):
        raise PipelineContractError(
            "check_prepared_orders: a preserving stage changed rows or their order"
        )
    check_raw_orders(frame)

    paid = frame["is_paid"]
    paid_missing_amount = paid & frame["amount"].isna()
    if paid_missing_amount.any():
        order_ids = _examples(frame["order_id"], paid_missing_amount)
        raise PipelineContractError(
            f"check_prepared_orders: paid orders need amount: {order_ids}"
        )
    if frame.loc[paid, "paid_amount"].ne(frame.loc[paid, "amount"]).any():
        raise PipelineContractError(
            "check_prepared_orders: paid rows must preserve amount"
        )
    if frame.loc[~paid, "paid_amount"].ne(0).any():
        raise PipelineContractError(
            "check_prepared_orders: non-paid rows must contribute zero"
        )
    return frame


def prepare_orders(frame: pd.DataFrame, *, timezone: str) -> pd.DataFrame:
    """Run the checked order pipeline and return a deterministic order-level table."""

    if not isinstance(frame, pd.DataFrame):
        raise PipelineContractError("prepare_orders: expected a pandas DataFrame")
    source = frame.copy(deep=True)
    source_index = source.index.copy()
    source_rows = len(source)

    return (
        source.pipe(check_raw_orders)
        .pipe(normalize_order_fields)
        .pipe(check_normalized_orders, expected_index=source_index)
        .pipe(add_time_columns, timezone=timezone)
        .pipe(add_paid_metrics)
        .pipe(
            check_prepared_orders,
            expected_index=source_index,
            expected_rows=source_rows,
        )
        .sort_values("order_id", kind="stable")
        .reset_index(drop=True)
    )
