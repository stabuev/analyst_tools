Проверка перед уроком

Ответьте до чтения: результат поможет заметить исходные предположения.

01

Две таблицы содержат разные столбцы, а строки нужно сопоставить по order_id. Какая операция соответствует задаче?

Когда строки двух таблиц нужно сопоставить по бизнес-ключу и добавить столбцы, это задача merge. Concat не ищет соответствия ключей.

02

Что означает grain «одна строка на заказ» для объявленного ключа order_id?

Grain задаёт смысл строки, поэтому полный бизнес-ключ целевой таблицы должен однозначно идентифицировать строку; индекс и порядок являются отдельными свойствами.

Concat, партии данных и порядок строк

merge сопоставляет строки по ключу, а concat складывает одинаковые по смыслу партии строк. Успешный вызов ещё не доказывает, что партии совместимы.

Тип: Build

Треки: Core

Пререквизиты: 03/06

Время: ~45 минут

Результат: выбирает concat вместо merge для одинаковых по grain партий строк, проверяет схему, dtype, происхождение и пересечения бизнес-ключей и задаёт воспроизводимый порядок результата.

Цели обучения

После урока вы сможете:

  • отличить добавление строк через concat от сопоставления строк через merge;
  • до объединения объявить общий grain, полный бизнес-ключ, схему и dtype партий;
  • предсказать число строк и выполнить вертикальный pd.concat с новым техническим индексом;
  • обнаружить дрейф схемы, dtype и пересечение бизнес-ключей;
  • сохранить происхождение каждой строки в обычном столбце;
  • задать полный воспроизводимый порядок с бизнес-ключом как tie-breaker;
  • проверить строки, grain, схему, dtype, происхождение и индекс результата.

Где мы находимся в маршруте

В 02/05 мы уже складывали однотипные наблюдения через np.concatenate. Там совместимость означала согласованные размеры массивов, а одна перестановка сохраняла связь между элементами нескольких массивов. pandas переносит тот же механизм на таблицы:

В 03/06 мы разобрали другой вид объединения — таблицы с разными ролями:

text
orders             -> одна строка на заказ
order_rollup       -> одна строка на заказ, другие столбцы
merge по order_id  -> сопоставить строки и добавить столбцы

Теперь возникает соседняя, но другая рабочая задача. Заказы приходят несколькими файлами:

text

orders_part_02     -> одна строка на заказ, те же столбцы

Именно поэтому concat расположен сразу после joins. Студент уже умеет объявлять grain, бизнес-ключ и dtype, а теперь учится выбирать между двумя способами объединения:

Проблема

Сервис выгружает заказы двумя частями. В первой партии:

order_id status amount
O1001 paid 1200.0
O1002 paid 800.0

Во второй:

order_id status amount
O1003 refunded 5500.0
O1004 paid пропуск

У обеих таблиц один контракт:

text
grain              -> одна строка на заказ
бизнес-ключ        -> order_id
столбцы            -> order_id, status, amount
dtype              -> string, string, Float64
пропуск в amount   -> допустим и остаётся неизвестностью

Нужно получить четыре строки, а не искать пары заказов между файлами. merge здесь задаёт неверный вопрос: он попытался бы сопоставить O1001 из одной таблицы с O1001 из другой и расположить поля рядом. Нам нужно просто добавить вторую порцию наблюдений.

Кажется, что достаточно одной строки:

python
orders = pd.concat([part_01, part_02])

Но pandas не знает предметного контракта. Он может технически собрать результат, даже если:

  • во второй партии исчез обязательный столбец;
  • появился неожиданный новый столбец;
  • amount прочитан как строка;
  • один order_id попал в обе партии;
  • старые технические индексы повторяются;
  • порядок входных файлов изменился между запусками;
  • происхождение проблемной строки потерялось.

Исключения может не быть. Поэтому задача урока — не запомнить pd.concat, а превратить «сложить файлы» в проверяемую операцию над партиями одного типа.

Концепция

Сначала выберите операцию по смыслу

До API сформулируйте, что должно измениться:

text
добавить признаки существующим сущностям -> merge по ключу
добавить наблюдения того же типа       -> concat по строкам
переставить уже имеющиеся факты        -> reshape в 03/08

Количество одинаковых столбцов не является достаточным признаком. Две таблицы могут иметь одинаковые названия и всё равно описывать разные сущности или разные grain.

Вертикальный concat добавляет строки

У DataFrame две оси:

  • axis=0, или ось индекса, идёт вниз по строкам;
  • axis=1, или ось столбцов, идёт вправо.

Для партий наблюдений нужен axis=0:

python
combined = pd.concat(
    [part_01, part_02],
    axis=0,
    ignore_index=True,
    sort=False,
)

Это можно прочитать так:

text
возьми строки первой таблицы
затем строки второй таблицы
согласуй их по названиям столбцов
создай новый технический индекс 0..n-1

Здесь sort=False относится не к порядку строк. При axis=0 он запрещает pandas сортировать метки другой оси — названия столбцов — во время их согласования. Порядок строк задаётся отдельно через sort_values.

concat не проверяет order_id и не ищет пары. Строка O1001 из двух партий даст две строки результата. Если целевой grain обещает одну строку на заказ, пересечение нужно обнаружить отдельной проверкой.

Совместимость начинается с grain, затем проверяется технически

Партия данных — отдельная поставка одного логического набора. Она не создаёт новый тип сущности и не меняет grain. Для безопасного объединения партии должны разделять один контракт:

  1. Одинаковый grain. Одна строка означает сущность одного типа.
  2. Один полный бизнес-ключ. Одни и те же столбцы проверяют уникальность строки.
  3. Одинаковая схема. Набор столбцов и их смысл совпадают.
  4. Одинаковые dtype. Значения уже приведены по контракту 03/02.
  5. Согласованная семантика пропусков. NA означает одну и ту же неизвестность.

Совпадение названий проверяет только часть контракта: amount может означать сумму заказа в одной партии и сумму позиции в другой. Если повтор ключа является версией, это нужно выразить новым grain и полным ключом, например order_id + effective_at, а не скрывать через (source_batch, order_id) или drop_duplicates(keep="last").

Что pandas сделает при дрейфе столбцов

По умолчанию concat согласует столбцы по их меткам и использует объединение столбцов. Новый channel появится с NA в старых партиях. join="inner", наоборот, молча оставит только общие столбцы. Оба технически успешных результата способны спрятать изменение поставки, поэтому точную схему нужно сравнивать до concat.

Порядок столбцов не несёт того же смысла, что их названия. Артефакт разрешает разный физический порядок, но переставляет столбцы каждой партии по схеме первой и отражает это в аудите.

Dtype нужно согласовать до объединения

Если amount имеет Float64 в первой партии и string во второй, pandas может выбрать общий, более слабый dtype. Правильная последовательность знакома по 03/02:

text
сырая партия
-> отдельно разобрать и проверить значения
-> привести к объявленному dtype
-> только затем объединять

Артефакт не исправляет типы на лету: иначе источник дрейфа исчезнет из evidence.

Для расширенных типов одного имени бывает недостаточно, поэтому артефакт сравнивает сами dtype-объекты. Категориальные словари подробно появятся в 03/10.

Базовая сверка — сумма строк партий

Если операция лишь добавляет наблюдения, ожидаемое число строк известно заранее:

text
result_rows = rows(part_01) + rows(part_02) + ... + rows(part_n)

Для партий на 40, 35 и 25 строк ожидается 100 строк. Результат на 99 или 101 строку нарушает контракт независимо от того, выглядит ли таблица правдоподобно.

Эта сверка не заменяет проверку бизнес-ключа:

  • 100 строк могут содержать два представления одного заказа и не содержать другого;
  • уникальный order_id не доказывает, что все ожидаемые партии загружены;
  • обе проверки отвечают на разные вопросы.

Происхождение лучше хранить обычным столбцом

Чтобы по ошибочной строке найти исходную поставку, добавьте происхождение до concat:

python
part = frame.copy()
part["source_batch"] = batch_name

Так provenance остаётся доступным фильтрации, группировке и экспорту. Параметр keys создал бы MultiIndex, но в основном маршруте происхождение остаётся обычным столбцом, а индекс — технической осью.

ignore_index=True решает только вопрос технического индекса

Каждая партия часто получает собственный RangeIndex 0..n-1. Без ignore_index=True метки повторятся: 0, 1, 0, 1.

Если индекс не содержит бизнес-смысла, создайте новый:

python
pd.concat(parts, ignore_index=True)

Это не удаляет повторные order_id: как и в 03/01, индекс и бизнес-ключ — разные контракты.

Порядок поступления не равен бизнес-порядку

Вертикальный concat сохраняет последовательность переданных объектов и строк внутри них. Но список файлов может измениться из-за обхода каталога, параллельной загрузки или новой партии. Значит, «строка была первой» не является устойчивым бизнес-фактом.

Если порядок нужен для сравнения, экспорта или воспроизводимого теста, задайте его явно:

python
combined.sort_values(
    by=["status", "order_id"],
    na_position="last",
    ignore_index=True,
)

status группирует строки, а уникальный order_id становится tie-breaker — дополнительным правилом для равных значений. Без него порядок нескольких paid-заказов может зависеть от входной последовательности партий.

Как и в 02/05, стабильная сортировка сохраняет исходный порядок равных элементов, но не делает неполный ключ сортировки полным. Если исходный порядок партий случаен, его стабильное сохранение тоже не даёт воспроизводимости. Поэтому последним правилом должен быть уникальный бизнес-ключ.

Почему concat(axis=1) не заменяет merge

pd.concat([orders, users], axis=1) располагает столбцы рядом, выравнивая строки по меткам индекса. Одинаковый RangeIndex не доказывает совпадение user_id. Для сопоставления сущностей используйте merge из 03/06; axis=1 уместен только при заранее проверенной общей индексной оси и здесь отдельно не изучается.

Граница урока

Обязательный минимум — вертикальный concat одинаковых по grain партий, проверка схемы, dtype, строк и ключа, provenance, новый индекс и полный порядок. MultiIndex, горизонтальное выравнивание, merge_ordered, merge_asof, потоковая обработка и выбор версии сущности требуют других задач и остаются за границей урока.

Соберите это

Сначала воспроизведите механизм без pandas. Есть две партии как списки словарей:

python
part_01 = [
    {"order_id": "O1001", "status": "paid", "amount": 1200.0},
    {"order_id": "O1002", "status": "paid", "amount": 800.0},
]
part_02 = [
    {"order_id": "O1003", "status": "refunded", "amount": 5500.0},
    {"order_id": "O1004", "status": "paid", "amount": None},
]

Шаг 1. Объявите общий контракт

До объединения запишите:

text
grain         -> одна строка на заказ
key           -> order_id
schema        -> order_id, status, amount
expected rows -> 2 + 2 = 4

Шаг 2. Добавьте происхождение и строки

python
manual = []
for batch_name, rows in [("part-01", part_01), ("part-02", part_02)]:
    for row in rows:
        manual.append({**row, "source_batch": batch_name})

Здесь виден механизм, который скроет concat:

  1. строки не сопоставляются между собой;
  2. каждая строка переносится один раз;
  3. схема должна быть общей;
  4. происхождение добавляется до потери границы партий.

Шаг 3. Проверьте ключ и порядок

python
keys = [row["order_id"] for row in manual]
assert len(manual) == len(part_01) + len(part_02)
assert None not in keys
assert len(keys) == len(set(keys))

manual = sorted(manual, key=lambda row: row["order_id"])

Теперь намеренно добавьте O1002 во вторую партию. Сумма строк всё ещё сойдётся, но уникальность ключа нарушится. Это показывает, почему одна сверка не заменяет другую.

Используйте это

Минимальный вызов pandas

Для уже типизированных таблиц:

python
import pandas as pd

part_01_df = pd.DataFrame(part_01).astype(
    {"order_id": "string", "status": "string", "amount": "Float64"}
)
part_02_df = pd.DataFrame(part_02).astype(
    {"order_id": "string", "status": "string", "amount": "Float64"}
)

combined = pd.concat(
    [part_01_df, part_02_df],
    axis=0,
    ignore_index=True,
    sort=False,
)

Этот вызов выполняет саму операцию, но не проверяет предметный контракт. Поэтому рабочий артефакт принимает именованные партии и ключ:

python
from outputs.batch_concat import concat_batches

orders, audit = concat_batches(
    {
        "part-01": part_01_df,
        "part-02": part_02_df,
    },
    key=["order_id"],
)

Функция выполняет последовательность:

text
проверить mapping и имена партий
-> проверить DataFrame и уникальные названия столбцов
-> сравнить точную схему и dtype
-> проверить non-missing/non-blank бизнес-ключ
-> добавить source_batch на копиях
-> pd.concat(axis=0, ignore_index=True)
-> сверить сумму строк
-> отклонить пересечение полного ключа
-> отсортировать по ключу
-> вернуть DataFrame и audit

Явный ведущий порядок

Если для отчёта сначала нужен порядок загрузки, передайте существующий типизированный столбец:

python
orders, audit = concat_batches(
    batches,
    key=["order_id"],
    sort_by=["loaded_sequence"],
)

Артефакт добавит отсутствующие столбцы полного ключа в конец сортировки:

text
effective sort -> loaded_sequence, order_id

Так равные loaded_sequence получают однозначный tie-breaker. Функция сортирует только по возрастанию: редкие варианты направления лучше задавать отдельной прозрачной стадией, чем раздувать первый контракт concat.

Что находится в аудите

python
{
    "batch_rows": {"part-01": 2, "part-02": 2},
    "result_rows": 4,
    "schema": ["order_id", "status", "amount"],
    "dtypes": {"order_id": "string", "status": "string", "amount": "Float64"},
    "key": ["order_id"],
    "effective_sort_columns": ["order_id"],
    "row_reconciliation_passed": True,
    "grain_valid": True,
}

Полный отчёт дополнительно сохраняет полученный порядок партий, имя provenance-столбца, нормализацию порядка столбцов и политику индекса. Эти поля полезны при расследовании, но не меняют основной критерий успешности.

Это не сертификат качества всех данных. Аудит подтверждает только заявленные инварианты операции: совместимость партий, полноту переноса строк, уникальность объявленного ключа и воспроизводимый порядок.

Сломайте это

1. Выбрать неверную операцию или ось

merge начнёт искать пары по ключу, а concat(axis=1) выровняет строки по техническому индексу. Ни одна операция не означает «добавить новые заказы». Сначала сформулируйте, добавляются наблюдения или признаки, и только затем выбирайте API.

2. Смешать разные grain, схемы или dtype

Заказы и товарные позиции могут иметь похожие столбцы, но разный смысл строки. Новый channel, исчезнувший amount или строковый dtype суммы тоже являются изменениями контракта. join="outer" способен скрыть их через NA, а join="inner" — через потерю столбца. Оба варианта требуют явного решения до concat.

3. Узаконить пересечение ключей техническим приёмом

Разные индексы и названия партий не превращают два O1001 в разные заказы. Добавление source_batch в бизнес-ключ или безусловный drop_duplicates(keep="last") лишь прячет конфликт. Для версий нужен новый объявленный grain и предметное правило выбора.

4. Проверить только число строк

Сумма строк может сойтись, даже если один заказ представлен дважды, а другой отсутствует. Поэтому row reconciliation и уникальность полного ключа проверяются независимо.

5. Потерять происхождение

После concat видно неверное значение, но уже неизвестно, какую партию исправлять. source_batch нужно добавить до объединения; технический индекс происхождение не заменяет.

6. Положиться на случайный или неполный порядок

Порядок файлов может измениться между запусками, а sort_values("status") не определяет порядок внутри одинаковых статусов. Добавьте полный бизнес-ключ как последний tie-breaker и только после этого сбрасывайте индекс.

Quiz · 6 вопроса

Проверьте себя

Ответьте после практики. Объяснение появится сразу после выбора.

01

Январский и февральский файлы имеют одну строку на заказ и одинаковые столбцы. Нужно собрать годовую таблицу. Какой первый выбор наиболее уместен?

Это одинаковые по смыслу партии строк, поэтому их добавляют вдоль оси строк. До concat нужно проверить совместимость контракта.

02

В одной партии появился новый столбец channel, а в остальных его нет. Почему опасно сразу вызвать concat с обычными настройками?

По умолчанию concat согласует другую ось через объединение меток. Технически успешный результат может замаскировать неожиданное изменение схемы.

03

Один order_id встретился в двух дневных партиях, хотя итоговый grain — одна строка на заказ. Что делать?

Разные файлы и индексы не меняют целевой grain. Дубликат требует предметного решения: исправить партии, расширить полный ключ или явно выбрать версию.

04

Почему concat(axis=1) обычно не заменяет merge по бизнес-ключу?

Горизонтальный concat выравнивает объекты по индексу. Если индекс технический или по-разному упорядочен, столбцы могут оказаться рядом с неверными сущностями.

05

Таблица отсортирована только по неполному полю status, внутри которого много равных значений. Что нужно для воспроизводимого полного порядка?

Неполный ключ сортировки задаёт лишь группы равных значений. Полный уникальный бизнес-ключ однозначно упорядочивает строки внутри каждой группы.

06

После объединения партий 40, 35 и 25 строк получено 99 строк. Какой вывод следует сделать первым?

Для добавления строк базовый инвариант — result rows = сумма строк партий. Причина потери ещё неизвестна, но результат нельзя считать проверенным.

"""Contract-first row-wise concatenation of already validated pandas batches.

The public function :func:`concat_batches` accepts a named mapping of same-grain,
same-schema DataFrames. It validates the contract before concatenation, records batch
provenance, rejects overlapping business keys and returns a deterministically ordered
result with an audit report. It does not read files, parse raw values or provide a CLI.
"""

from __future__ import annotations

from collections.abc import Mapping, Sequence
from typing import Any

import pandas as pd

__all__ = ["ConcatContractError", "concat_batches"]


class ConcatContractError(ValueError):
    """Raised when row-wise concatenation would violate the declared contract."""


def _column_names(names: Sequence[str], *, argument: str) -> list[str]:
    if isinstance(names, (str, bytes)):
        raise ConcatContractError(f"{argument} must be a sequence of column names")
    result = list(names)
    if not result:
        raise ConcatContractError(f"{argument} must not be empty")
    if any(not isinstance(name, str) or not name.strip() for name in result):
        raise ConcatContractError(
            f"{argument} must contain non-blank string column names"
        )
    if len(result) != len(set(result)):
        raise ConcatContractError(f"{argument} must not contain duplicate names")
    return result


def _batch_name(name: object) -> str:
    if not isinstance(name, str) or not name.strip():
        raise ConcatContractError("batch names must be non-blank strings")
    return name


def _frame(value: object, *, batch: str) -> pd.DataFrame:
    if not isinstance(value, pd.DataFrame):
        raise ConcatContractError(f"batch {batch!r} must be a pandas DataFrame")
    if not value.columns.is_unique:
        raise ConcatContractError(f"batch {batch!r} column labels must be unique")
    return value


def _blank_mask(series: pd.Series) -> pd.Series:
    return series.map(
        lambda value: isinstance(value, str) and not value.strip()
    ).astype("boolean")


def _validate_key_values(
    frame: pd.DataFrame,
    *,
    batch: str,
    keys: Sequence[str],
) -> None:
    invalid = frame.loc[:, keys].isna().any(axis=1)
    for key in keys:
        invalid |= _blank_mask(frame[key]).fillna(False)
    if invalid.any():
        labels = frame.index[invalid].tolist()[:5]
        raise ConcatContractError(
            f"batch {batch!r} business key must be non-missing and non-blank; "
            f"row labels: {labels}"
        )


def _dtype_map(frame: pd.DataFrame) -> dict[str, Any]:
    """Return dtype objects so extension-type metadata participates in equality."""

    return {column: frame[column].dtype for column in frame.columns}


def _dtype_labels(dtypes: Mapping[str, Any]) -> dict[str, str]:
    """Make dtype objects readable and serializable in errors and audit output."""

    return {column: str(dtype) for column, dtype in dtypes.items()}


def concat_batches(
    batches: Mapping[str, pd.DataFrame],
    *,
    key: Sequence[str],
    sort_by: Sequence[str] | None = None,
    source_column: str = "source_batch",
) -> tuple[pd.DataFrame, dict[str, Any]]:
    """Append same-grain batches and verify one reproducible result.

    Parameters
    ----------
    batches:
        Non-empty mapping ``batch name -> DataFrame``. Every frame must contain exactly
        the same columns with the same pandas dtypes. Column order may differ and is
        normalized to the first batch.
    key:
        Complete business key of the target row grain. Values must be non-missing,
        non-blank and unique across the combined result.
    sort_by:
        Optional leading business sort columns. Missing key columns are appended as
        deterministic tie-breakers. If omitted, the complete key defines the order.
    source_column:
        New string column that records the originating batch.

    Returns
    -------
    tuple[pandas.DataFrame, dict]
        A new DataFrame with a fresh ``RangeIndex`` and an audit report. Inputs are not
        modified.
    """

    if not isinstance(batches, Mapping) or not batches:
        raise ConcatContractError("batches must be a non-empty mapping")
    keys = _column_names(key, argument="key")
    if not isinstance(source_column, str) or not source_column.strip():
        raise ConcatContractError("source_column must be a non-blank string")

    named_frames: list[tuple[str, pd.DataFrame]] = []
    for raw_name, raw_frame in batches.items():
        name = _batch_name(raw_name)
        named_frames.append((name, _frame(raw_frame, batch=name)))

    reference_name, reference = named_frames[0]
    reference_columns = reference.columns.tolist()
    reference_set = set(reference_columns)
    if source_column in reference_set:
        raise ConcatContractError(
            f"source column already exists in input schema: {source_column}"
        )
    missing_key_columns = sorted(set(keys) - reference_set)
    if missing_key_columns:
        raise ConcatContractError(
            f"business key columns are missing from schema: {missing_key_columns}"
        )

    leading_order = keys if sort_by is None else _column_names(
        sort_by, argument="sort_by"
    )
    missing_sort_columns = sorted(set(leading_order) - reference_set)
    if missing_sort_columns:
        raise ConcatContractError(
            f"sort columns are missing from schema: {missing_sort_columns}"
        )
    effective_order = [*leading_order, *(name for name in keys if name not in leading_order)]

    reference_dtypes = _dtype_map(reference)
    normalized_order_batches: list[str] = []
    parts: list[pd.DataFrame] = []
    batch_rows: dict[str, int] = {}

    for name, frame in named_frames:
        columns = frame.columns.tolist()
        missing = sorted(reference_set - set(columns))
        extra = sorted(set(columns) - reference_set)
        if missing or extra:
            raise ConcatContractError(
                f"batch {name!r} schema differs from {reference_name!r}; "
                f"missing={missing}, extra={extra}"
            )
        if source_column in frame.columns:
            raise ConcatContractError(
                f"source column already exists in batch {name!r}: {source_column}"
            )

        actual_dtypes = _dtype_map(frame.loc[:, reference_columns])
        dtype_mismatches = {
            column: {
                "expected": str(reference_dtypes[column]),
                "actual": str(actual_dtypes[column]),
            }
            for column in reference_columns
            if actual_dtypes[column] != reference_dtypes[column]
        }
        if dtype_mismatches:
            raise ConcatContractError(
                f"batch {name!r} dtypes differ from {reference_name!r}: "
                f"{dtype_mismatches}"
            )

        _validate_key_values(frame, batch=name, keys=keys)
        if columns != reference_columns:
            normalized_order_batches.append(name)

        part = frame.loc[:, reference_columns].copy()
        part[source_column] = pd.array([name] * len(part), dtype="string")
        parts.append(part)
        batch_rows[name] = len(part)

    expected_rows = sum(batch_rows.values())
    combined = pd.concat(parts, axis=0, ignore_index=True, sort=False)
    if len(combined) != expected_rows:
        raise ConcatContractError(
            f"row reconciliation failed: expected {expected_rows}, got {len(combined)}"
        )

    combined_dtypes = _dtype_map(combined.loc[:, reference_columns])
    changed_dtypes = {
        column: {
            "expected": str(reference_dtypes[column]),
            "actual": str(combined_dtypes[column]),
        }
        for column in reference_columns
        if combined_dtypes[column] != reference_dtypes[column]
    }
    if changed_dtypes:
        raise ConcatContractError(
            f"concat changed declared dtypes: {changed_dtypes}"
        )

    duplicated = combined.duplicated(keys, keep=False)
    if duplicated.any():
        examples = (
            combined.loc[duplicated, [*keys, source_column]]
            .head(8)
            .to_dict(orient="records")
        )
        raise ConcatContractError(
            "business key overlaps within or across batches; "
            f"duplicate row examples: {examples}"
        )

    sort_kwargs: dict[str, Any] = {
        "by": effective_order,
        "na_position": "last",
        "ignore_index": True,
    }
    if len(effective_order) == 1:
        sort_kwargs["kind"] = "stable"
    result = combined.sort_values(**sort_kwargs)

    if not isinstance(result.index, pd.RangeIndex):
        raise ConcatContractError("result must have a fresh RangeIndex")
    if result.duplicated(keys).any():
        raise ConcatContractError("result does not satisfy the declared row grain")

    audit: dict[str, Any] = {
        "batch_order_received": [name for name, _ in named_frames],
        "batch_rows": batch_rows,
        "input_rows": expected_rows,
        "result_rows": len(result),
        "schema": reference_columns.copy(),
        "dtypes": _dtype_labels(reference_dtypes),
        "key": keys.copy(),
        "source_column": source_column,
        "column_order_normalized_batches": normalized_order_batches,
        "effective_sort_columns": effective_order,
        "row_reconciliation_passed": len(result) == expected_rows,
        "grain_valid": True,
        "index_policy": "fresh RangeIndex after concat and sort",
    }
    return result, audit
