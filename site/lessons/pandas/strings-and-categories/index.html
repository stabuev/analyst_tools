01

В столбце статуса встречаются строки "paid" и " paid ". Что произойдет при groupby до нормализации?

GroupBy использует фактические значения ключа. Внешние пробелы являются частью строки, пока отдельное правило нормализации их не удалило.

Непустая исходная строка после преобразования стала missing. Какой вывод безопасен по модели урока 03/02?

Missing в результате не доказывает missing в источнике. Маска исходных непустых значений нужна, чтобы обнаружить потерю при преобразовании.

Строки и категориальные типы

Сначала сделайте значение сопоставимым, затем проверьте его смысл и только после этого кодируйте как категорию.

Тип: Build Треки: Core Пререквизиты: 03/09 Время: ~105 минут Результат: нормализует и проверяет строковые признаки, применяет стабильный категориальный словарь и сохраняет отдельные свидетельства о пропусках и неизвестных значениях.

Цели обучения

После урока вы сможете:

  • объяснить, почему строки, которые выглядят одинаково для человека, могут давать разные группы и ключи;
  • применять nullable string и строковый accessor .str без потери пропусков и меток индекса;

  • создавать явный CategoricalDtype со стабильным словарём и осмысленным порядком;
  • отличать известную категорию, неизвестное непустое значение, агрегат other и пропуск;
  • сохранять evidence до потенциально необратимого объединения значений.

На что опирается урок

В 03/02 вы уже объявляли dtype и nullable-политику столбца. Там были введены nullable string, pd.NA, isna() и важное различие между пустым значением и непустым невалидным токеном. В 03/03 вы строили маски isin и не разрешали NA неявно. В 03/04 применяли операции над Series, сохраняли индекс и избегали построчного apply там, где есть табличная операция.

Уроки 03/05 и 03/06 показали цену несогласованных измерений:

  • groupby создаёт отдельную группу для каждой фактической метки;
  • merge сопоставляет точные ключи, а не «похожие по смыслу» строки;
  • библиотека не знает, что Addon и add-on обозначают одно и то же.

В 03/09 вы отделяли исходную строку времени от разобранного Timestamp и проверяли непустые значения, потерянные преобразованием. Здесь используется тот же принцип:

text
сырой токен
→ прозрачное преобразование
→ отдельная проверка потерянных или неизвестных значений
→ только затем рабочий dtype

Это последний типовой этап очистки перед 03/11. В следующем уроке числовые, временные и строковые преобразования будут собраны в один проверяемый pipeline.

Проблема

В таблице товарных позиций одна бизнес-категория записана четырьмя способами:

order_id Исходное category Как читает человек Как сравнивает pandas
O1001 " add-on " add-on отдельная строка с пробелами
O1001 "Addon" add-on отдельная строка без дефиса
O1003 "ADD-ON" add-on отдельная строка в другом регистре
O1007 "add-on" add-on ещё одна точная метка

Прямой расчёт выглядит корректно:

python
items.groupby("category", dropna=False)["quantity"].sum()

Но он ответит на технический вопрос «сколько строк имеет каждое точное представление», а не на бизнес-вопрос «сколько товаров каждой категории продано». Одна категория распадётся на несколько групп, и итог будет правдоподобным: все строки учтены, сумма сходится, исключения нет.

Та же проблема проявится в других операциях:

  • merge не присоединит справочник для " add-on ", если его ключ — "add_on";
  • фильтр eq("add_on") пропустит только одно точное написание;
  • value_counts покажет раздробленный словарь;
  • сортировка расположит текст лексикографически, а не в бизнес-порядке;
  • новая категория из свежей выгрузки может незаметно стать пропуском при неосторожном приведении к закрытому category.

Задача поэтому шире, чем «привести строки к нижнему регистру». Нужно объявить:

  1. какие технические различия не меняют смысл;
  2. какие разные токены являются известными синонимами;
  3. какие канонические значения допустимы;
  4. что делать с новым непустым значением;
  5. как сохранить свидетельства о преобразовании.

Концепция

Четыре состояния нельзя смешивать

После очистки строковый признак может находиться в одном из четырёх состояний:

Состояние Пример Что известно Типичное решение
Известная категория premium значение входит в объявленный словарь принять
Известный синоним Premium Plan → premium отображение утверждено явно сохранить отображение в аудите
Unknown enterprise значение есть, но его смысл не разрешён контрактом остановить или явно отправить в other
Missing pd.NA или пустая строка по принятому правилу значения нет сохранить пропуск или применить отдельную nullable-политику

Unknown и missing отвечают на разные вопросы.

  • pd.NA: факт отсутствует.
  • enterprise: факт присутствует, но текущий словарь его не знает.

Если оба состояния превратить в один пропуск, аналитик не отличит неполные данные от изменения продуктового справочника. Если оба превратить в other, отсутствие факта станет реальной бизнес-категорией.

string задаёт текстовое хранение, но не смысл

Начинайте со строковой Series:

python
raw = items["category"].astype("string")

Явный nullable string нужен по трём причинам:

  • столбец больше не является общим контейнером object;
  • пропуски доступны через isna();
  • строковые операции вызываются через единый accessor .str.

.str применяет операцию к каждому непропущенному значению Series и сохраняет её индекс. Это важно для последующего присваивания обратно в DataFrame: результат остаётся связан с исходными строками метками, а не только длиной.

python
trimmed = raw.str.strip()

assert trimmed.index.equals(raw.index)
assert trimmed.isna().equals(raw.isna())

Однако dtype string не сообщает, что basic разрешён, enterprise неизвестен, а Premium является вариантом premium. Эти решения относятся к отдельному предметному контракту.

Нормализация не угадывает бизнес-смысл

Техническая нормализация удаляет различия, которые договорились считать несущественными:

  • совместимое Unicode-представление;
  • внешние пробелы;
  • регистр;
  • несколько согласованных разделителей;
  • пустой результат после очистки.

Для категориальных кодов этого урока используем правило:

text
NFKC
→ strip
→ casefold
→ пробелы, дефисы и подчёркивания заменить одним _
→ убрать крайние _
→ пустой результат считать missing

Примеры:

Исходное значение После технической нормализации
" Premium " premium
"ADD-ON" add_on
"add on" add_on
"Ａdd‑On" add_on
" " pd.NA

NFKC приводит совместимые Unicode-формы к общему представлению. Например, полноширинная латинская Ａ становится обычной A. casefold предназначен для регистронезависимого сравнения и работает шире, чем lower.

Это правило не является универсальной очисткой любого текста. Его разумно применять к машинным кодам, тегам, статусам и другим контролируемым значениям. Для имён людей, адресов, комментариев и юридических названий такая нормализация может удалить значимое различие. Там нужно хранить исходный текст и проектировать отдельный предметный контракт.

Порядок этапов является частью контракта

Безопасный pipeline:

text
1. техническая нормализация
2. проверка структуры строки
3. явная карта синонимов
4. проверка канонического словаря
5. политика unknown
6. создание category

Почему именно так:

  • проверять " ADD-ON " по каноническому словарю слишком рано: технические различия создадут ложный unknown;
  • применять aliases до нормализации неудобно: словарю придётся перечислять каждый регистр, пробел и вариант дефиса;
  • приводить к category до проверки опасно: потерянное значение уже будет трудно отличить от исходного пропуска.

Карта aliases содержит только утверждённые предметные соответствия:

python
aliases = {
    "addon": "add_on",
}

Техническое правило не должно самостоятельно решать, что pro, premium и paid — один тариф. Такое объединение требует знания домена и отдельного изменения контракта.

Минимальный строковый набор: нормализовать, проверить, извлечь

У .str много методов. Для основного маршрута сейчас нужны три вида действий.

1. Нормализация

python
normalized = (
    raw
    .str.normalize("NFKC")
    .str.strip()
    .str.casefold()
    .str.replace(r"[\s_\-‐‑‒–—]+", "_", regex=True)
    .str.strip("_")
)

Регулярное выражение здесь выполняет узкую работу:

  • квадратные скобки обозначают один символ из перечисленного класса;
  • \s означает пробельный символ;
  • + означает один или несколько подряд;
  • вся последовательность заменяется одним подчёркиванием.

Полный язык регулярных выражений для этого урока не нужен.

2. Проверка всей строки

Для формата из двух заглавных латинских букв:

python
country = users["country"].astype("string").str.strip().str.upper()
matches_format = country.str.fullmatch(r"[A-Z]{2}")

fullmatch проверяет всю строку. contains отвечает на другой вопрос — встречается ли совпадение где-либо внутри:

Значение contains("[A-Z]{2}") fullmatch("[A-Z]{2}")
RU True True
RU-extra True False

Regex проверяет только форму. ZZ соответствует двум буквам, но не становится от этого реальным кодом страны. Семантическая допустимость всё равно проверяется словарём.

3. Извлечение структурированных частей

Если в одном текстовом поле записан составной токен, используйте именованные группы:

python
labels = pd.Series(
    ["plan:premium", "plan:basic", pd.NA],
    dtype="string",
)

parts = labels.str.extract(
    r"^(?P<kind>[a-z_]+):(?P<value>[a-z_]+)$"
)

Результат — DataFrame с колонками kind и value. Строка, не совпавшая с шаблоном, даст пропуски в извлечённых частях. Поэтому после extract нужно отдельно сравнить непустой источник с неразобранным результатом — так же, как вы делали для чисел и дат.

split, extractall и сложные регулярные выражения изучаются по мере появления реальной задачи. Каталог методов не заменяет модель проверки.

Category — словарь, codes и признак порядка

Категориальная Series хранит:

  1. массив допустимых значений categories;
  2. целочисленный code для каждой строки;
  3. флаг ordered.

Пример:

python
plan_dtype = pd.CategoricalDtype(
    categories=["trial", "basic", "premium"],
    ordered=True,
)
Значение Внутренний code
trial 0
basic 1
premium 2
missing -1

Codes являются внутренним представлением, а не бизнес-идентификаторами. Если изменить порядок словаря, code изменится. В отчёт и обменный файл нужно передавать значения и контракт, а не полагаться на число 0 или 1.

Пропуск не входит в categories. Он хранится в значениях отдельно и получает code -1. Именно поэтому неизвестное значение нельзя молча превращать в отсутствующее.

astype("category") выводит словарь из текущих данных

Короткая запись:

python
batch["plan"].astype("category")

создаёт словарь из значений конкретной порции. Это удобно для исследования, но слабо как контракт production-pipeline:

text
batch A → ["basic", "premium"]
batch B → ["basic", "enterprise", "premium"]

Одинаковый код создаёт разные dtype. Сравнение, конкатенация, сортировка и downstream- проверки становятся зависимыми от того, какие значения случайно встретились сегодня.

Явный CategoricalDtype фиксирует один словарь для всех порций:

python
plan_dtype = pd.CategoricalDtype(
    categories=["trial", "basic", "premium", "other"],
    ordered=True,
)

Неиспользованная сегодня категория остаётся частью контракта. Например, value_counts() для categorical может показать её с нулевой частотой. Это полезно: отсутствие наблюдений не стирает допустимый уровень шкалы.

Category не является валидатором неизвестных значений

Рассмотрим:

python
source = pd.Series(
    ["basic", "enterprise", pd.NA],
    dtype="string",
)

source.astype(
    pd.CategoricalDtype(["basic", "premium"])
)

В используемой версии pandas неизвестное enterprise при таком создании становится missing и получает code -1; pandas также предупреждает, что это поведение меняется в будущей версии. Исходный пропуск и новый тариф оказываются технически одинаковыми.

Если же categorical уже создан, присваивание значения вне словаря завершится ошибкой:

python
plans.iloc[0] = "enterprise"

Это два разных сценария, но вывод один: сначала самостоятельно сравните непустые канонические значения со словарём, затем вызывайте dtype-преобразование.

python
unknown = normalized.notna() & ~normalized.isin(allowed)

Политика other должна быть стабильной и наблюдаемой

Есть две основные политики unknown.

error

Остановить преобразование и показать значения с частотами:

text
unknown categories: 'enterprise': 12, 'legacy': 3

Это правильный default для ключей справочников, критичных статусов и небольших контролируемых словарей.

other

Явно объединить все неизвестные значения:

text
enterprise ┐
legacy     ├→ other
partner    ┘

Эта политика допустима, если downstream-решению не требуется различать новые значения. Но она необратима: после объединения по рабочему столбцу нельзя восстановить, какие токены составляли other.

Поэтому хороший контракт:

  • всегда включает other в итоговый dtype, даже если текущая порция не содержит unknown;
  • сохраняет частоты исходных unknown до объединения;
  • не отправляет в other настоящие пропуски;
  • позволяет установить порог или alert на рост доли other в рабочем pipeline.

Если other добавляется только при встрече нового значения, schema меняется от порции к порции. Это не стабильный контракт.

Ordered означает предметный порядок

Без ordered=True категории являются именованными уровнями без отношения «меньше — больше». При ordered=True сортировка и сравнения используют порядок categories:

python
plan_dtype = pd.CategoricalDtype(
    ["trial", "basic", "premium", "other"],
    ordered=True,
)

Это уместно, только если бизнес действительно объявил порядок отчёта или шкалы.

  • low < medium < high — естественный порядок.
  • trial < basic < premium — допустимый порядок отчёта, если он утверждён владельцем.
  • service < subscription < add_on — обычно просто произвольная последовательность, поэтому такая категория должна оставаться unordered.

Алфавитная сортировка строк не доказывает предметный порядок.

Когда category уместен

Хорошие кандидаты:

  • статус заказа из небольшого справочника;
  • тариф из управляемого словаря;
  • страна или канал привлечения при явном контракте;
  • уровень шкалы с утверждённым порядком;
  • повторяющийся признак, который downstream-инструмент должен воспринимать как categorical.

Плохие кандидаты:

  • свободный комментарий;
  • order_id или user_id;
  • URL, email и другие почти уникальные строки;
  • быстро растущий словарь без владельца;
  • число, превращённое в текст только ради уменьшения числа уникальных значений.

Экономия памяти возможна, когда значения многократно повторяются. Category хранит codes и отдельный словарь. Если число уникальных значений приближается к числу строк, словарь может занять столько же или больше памяти, чем строковый столбец. Универсального порога кардинальности нет — измеряйте memory_usage(deep=True) на своих данных. Главное назначение в этом уроке — явная семантика и стабильное поведение, а не обещание оптимизации.

Граница урока

В основном маршруте достаточно:

  • nullable string;
  • нормализации контролируемых токенов;
  • fullmatch и одного примера extract;
  • aliases;
  • unknown/missing policy;
  • явного CategoricalDtype;
  • ordered/unordered;
  • evidence до other.

Здесь не нужны fuzzy matching, транслитерация, стемминг, токенизация естественного языка, сложные regex-парсеры, locale-зависимое сопоставление имён и энциклопедия операций .cat. Эти темы требуют отдельных задач и более сильных допущений.

Соберите это

Сначала сделаем скрытые решения видимыми без pandas.

Шаг 1. Объявите техническое правило для одного токена

python
import re
import unicodedata


SEPARATORS = re.compile(r"[\s_\-‐‑‒–—]+")


def canonical_token(value: str | None) -> str | None:
    if value is None:
        return None

    normalized = unicodedata.normalize("NFKC", value)
    normalized = normalized.strip().casefold()
    normalized = SEPARATORS.sub("_", normalized).strip("_")

    return normalized or None

До запуска предскажите результат:

python
raw_values = [
    " add-on ",
    "Addon",
    "ＡDD‑ON",
    "subscription",
    "   ",
    None,
    "enterprise",
]

Ожидаем:

python
[
    "add_on",
    "addon",
    "add_on",
    "subscription",
    None,
    None,

Шаг 2. Примените явные aliases

    if value is not None

Quiz · 7 вопроса

Проверьте себя

Ответьте после практики. Объяснение появится сразу после выбора.

01

Какой порядок безопасно приводит грязный строковый признак к categorical dtype?

Сначала устраняются согласованные различия представления, затем применяются предметные решения. Category создается последним, когда unknown уже наблюдаемы.

02

Нужно проверить, что country целиком состоит ровно из двух заглавных латинских букв. Какой метод отвечает этому вопросу?

fullmatch требует совпадения всей строки. contains подтвердил бы и строку RU-extra, потому что в ней есть подходящий фрагмент.

03

Почему нельзя считать прямой astype(CategoricalDtype(...)) достаточной проверкой словаря?

Unknown нужно найти до потенциально lossy-преобразования. Иначе новый непустой токен и настоящий missing могут получить одно представление.

04

Что делает политику unknown="other" стабильной и проверяемой между порциями данных?

Стабильный dtype не зависит от состава текущей порции, а evidence сохраняет информацию, потерянную при объединении разных значений в other.

05

Когда ordered=True у категориального признака обоснован?

Ordered выражает смысл шкалы или утвержденный порядок отчета. Кардинальность, алфавит и память сами по себе такого отношения не создают.

06

Какой столбец является наиболее естественным кандидатом для category?

Category полезен для повторяющегося ограниченного словаря с явной семантикой. Идентификаторы и свободный текст обычно не соответствуют этой модели.

07

Почему правило NFKC → casefold → замена разделителей нельзя автоматически применять к именам и свободному тексту?

Агрессивная канонизация уместна для контролируемых кодов и тегов. В именах, адресах и комментариях представление может быть частью смысла.

from __future__ import annotations

import importlib.util
import unittest
from pathlib import Path

import pandas as pd

ROOT = Path(__file__).resolve().parents[1]
ARTIFACT = ROOT / "outputs" / "text_categories.py"
DATA = ROOT.parent / "data" / "tiny"
SPEC = importlib.util.spec_from_file_location("text_categories", ARTIFACT)
if SPEC is None or SPEC.loader is None:
    raise RuntimeError(f"cannot load {ARTIFACT}")
TEXT = importlib.util.module_from_spec(SPEC)
SPEC.loader.exec_module(TEXT)


class TextCategoriesTest(unittest.TestCase):
    def test_normalize_text_handles_unicode_case_and_separators(self) -> None:
        source = pd.Series([" Ａdd‑On ", "Straße", "STRASSE"], dtype="string")
        result = TEXT.normalize_text(source)
        self.assertEqual(result.tolist(), ["add_on", "strasse", "strasse"])

    def test_normalize_text_maps_blank_to_missing(self) -> None:
        result = TEXT.normalize_text(pd.Series(["", " \u00a0 ", None], dtype="string"))
        self.assertTrue(result.isna().all())

    def test_normalize_text_applies_aliases_after_technical_normalization(self) -> None:
        result = TEXT.normalize_text(
            pd.Series(["Addon", "add-on", " SERVICE "], dtype="string"),
            aliases={"ADDON": "add_on"},
        )
        self.assertEqual(result.tolist(), ["add_on", "add_on", "service"])

    def test_conflicting_normalized_aliases_fail(self) -> None:
        with self.assertRaisesRegex(TEXT.CategoryContractError, "conflicting alias"):
            TEXT.normalize_text(
                pd.Series(["add-on"], dtype="string"),
                aliases={"ADD-ON": "add_on", "add_on": "service"},
            )

    def test_normalize_text_preserves_labels_name_and_source(self) -> None:
        source = pd.Series([" Premium ", None], index=["u2", "u7"], name="plan", dtype="string")
        original = source.copy(deep=True)
        result = TEXT.normalize_text(source)
        self.assertTrue(result.index.equals(source.index))
        self.assertEqual(result.name, "plan")
        self.assertEqual(result.tolist()[0], "premium")
        self.assertTrue(pd.isna(result.iloc[1]))
        pd.testing.assert_series_equal(source, original)

    def test_fullmatch_checks_the_whole_value_and_keeps_missing_unknown(self) -> None:
        result = TEXT.fullmatch_text(
            pd.Series(["RU", "RU-extra", None], name="country", dtype="string"),
            r"[A-Z]{2}",
        )
        self.assertEqual(result.name, "country")
        self.assertEqual(str(result.dtype), "boolean")
        self.assertIs(bool(result.iloc[0]), True)
        self.assertIs(bool(result.iloc[1]), False)
        self.assertTrue(pd.isna(result.iloc[2]))

    def test_invalid_unknown_policy_fails_even_without_unknown_values(self) -> None:
        with self.assertRaisesRegex(TEXT.CategoryContractError, "unknown policy"):
            TEXT.categorize_text(
                pd.Series(["basic"], dtype="string"),
                categories=["basic"],
                unknown="typo",
            )

    def test_unknown_category_fails_with_evidence(self) -> None:
        with self.assertRaisesRegex(
            TEXT.CategoryContractError,
            "unknown categories: 'enterprise': 2",
        ):

from __future__ import annotations

import re
import unicodedata
from collections import Counter
from collections.abc import Mapping, Sequence
from typing import Any, NamedTuple

import pandas as pd

SEPARATOR_PATTERN = r"[\s_\-‐‑‒–—]+"
SEPARATOR_REGEX = re.compile(SEPARATOR_PATTERN)


class CategoryContractError(ValueError):
    """Raised when text or a categorical vocabulary breaks the declared contract."""


class CategoryContractResult(NamedTuple):
    """A categorical Series together with evidence collected before lossy mapping."""

    values: pd.Series
    audit: dict[str, Any]


def _canonical_token(value: str) -> str:
    if not isinstance(value, str):
        raise CategoryContractError("text contract values must be strings")
    normalized = unicodedata.normalize("NFKC", value).strip().casefold()
    return SEPARATOR_REGEX.sub("_", normalized).strip("_")


def _normalize_aliases(aliases: Mapping[str, str] | None) -> dict[str, str]:
    normalized: dict[str, str] = {}
    for raw_source, raw_target in (aliases or {}).items():
        source = _canonical_token(raw_source)
        target = _canonical_token(raw_target)
        if not source or not target:
            raise CategoryContractError("aliases cannot contain blank source or target")
        if source in normalized and normalized[source] != target:
            raise CategoryContractError(f"conflicting alias for {source!r}")
        normalized[source] = target
    return normalized


def normalize_text(
    series: pd.Series,
    *,
    aliases: Mapping[str, str] | None = None,
) -> pd.Series:
    """Normalize categorical text while preserving index, name, and missing values."""

    if not isinstance(series, pd.Series):
        raise CategoryContractError("normalize_text expects a pandas Series")

    result = (
        series.astype("string")
        .str.normalize("NFKC")
        .str.strip()
        .str.casefold()
        .str.replace(SEPARATOR_PATTERN, "_", regex=True)
        .str.strip("_")
    )
    blank = result.eq("").fillna(False)
    result = result.mask(blank, pd.NA)

    normalized_aliases = _normalize_aliases(aliases)
    if normalized_aliases:
        result = result.replace(normalized_aliases)

    result.name = series.name
    return result


def fullmatch_text(series: pd.Series, pattern: str) -> pd.Series:
    """Check the whole value against a format while keeping missing as unknown."""

    if not isinstance(series, pd.Series):
        raise CategoryContractError("fullmatch_text expects a pandas Series")
    if not isinstance(pattern, str) or not pattern:
        raise CategoryContractError("pattern must be a non-empty string")

    result = series.astype("string").str.fullmatch(pattern).astype("boolean")
    result.name = series.name
    return result


def _validate_categories(categories: Sequence[str]) -> list[str]:
    if isinstance(categories, (str, bytes)):
        raise CategoryContractError("categories must be a sequence of strings")
    declared = list(categories)
    if not declared:
        raise CategoryContractError("categories cannot be empty")
    if any(not isinstance(value, str) for value in declared):
        raise CategoryContractError("categories must contain only strings")
    if len(declared) != len(set(declared)):
        raise CategoryContractError("categories must be unique")

    normalized = [_canonical_token(value) for value in declared]
    if any(not value for value in normalized):
        raise CategoryContractError("categories cannot contain blank values")
    if normalized != declared:
        raise CategoryContractError("categories must already use canonical spelling")
    return declared


def categorize_text(
    series: pd.Series,
    *,
    categories: Sequence[str],
    aliases: Mapping[str, str] | None = None,
    unknown: str = "error",
    other_label: str = "other",
    ordered: bool = False,
) -> CategoryContractResult:
    """Normalize text, enforce a stable vocabulary, and retain audit evidence."""

    if unknown not in {"error", "other"}:
        raise CategoryContractError("unknown policy must be 'error' or 'other'")
    if not isinstance(ordered, bool):
        raise CategoryContractError("ordered must be true or false")

    declared = _validate_categories(categories)
    canonical_other = _canonical_token(other_label)
    if unknown == "other" and (not canonical_other or canonical_other != other_label):
        raise CategoryContractError("other_label must be a non-blank canonical string")

    raw = series.astype("string")
    normalized = normalize_text(series, aliases=aliases)
    unknown_mask = normalized.notna() & ~normalized.isin(declared)
    unknown_counts = Counter(str(value) for value in normalized.loc[unknown_mask].tolist())

    if unknown_counts and unknown == "error":
        rendered = ", ".join(
            f"{value!r}: {count}" for value, count in sorted(unknown_counts.items())
        )
        raise CategoryContractError(f"unknown categories: {rendered}")

    final_categories = declared.copy()
    prepared = normalized.copy()
    if unknown == "other":
        if canonical_other not in final_categories:
            final_categories.append(canonical_other)
        prepared = prepared.mask(unknown_mask, canonical_other)

    dtype = pd.CategoricalDtype(categories=final_categories, ordered=ordered)
    values = prepared.astype(dtype)
    values.name = series.name

    raw_blank = raw.notna() & raw.str.strip().eq("").fillna(False)
    changes: Counter[tuple[str, str]] = Counter()
    for raw_value, canonical_value in zip(raw.tolist(), normalized.tolist(), strict=True):
        if pd.isna(raw_value) or pd.isna(canonical_value):
            continue
        raw_text = str(raw_value)
        canonical_text = str(canonical_value)
        if raw_text != canonical_text:
            changes[(raw_text, canonical_text)] += 1

    audit: dict[str, Any] = {
        "categories": final_categories,
        "ordered": ordered,
        "unknown_policy": unknown,
        "source_missing_count": int(raw.isna().sum()),
        "blank_to_missing_count": int(raw_blank.sum()),
        "result_missing_count": int(values.isna().sum()),
        "unknown_count": int(unknown_mask.sum()),
        "unknown_values": dict(sorted(unknown_counts.items())),
        "canonical_counts": {
            category: int(values.eq(category).sum()) for category in final_categories
        },
        "normalization_changes": [
            {"raw": raw_value, "canonical": canonical, "count": count}
            for (raw_value, canonical), count in sorted(changes.items())
        ],
    }
    return CategoryContractResult(values=values, audit=audit)
